# @openfolia/render-typst

Renders a resolved manual (from `resolveManual` in `@openfolia/content-model`) to PDF with [Typst](https://typst.app).

```ts
const { manual } = resolveManual({
  manifest,
  variant,
  lang,
  config,
  loadModule,
});
const { source, assets, symbols } = renderTypst(manual, {
  subtitle: 'L-400 · Software 2.3 · EU',
  symbolPath: (id) => `symbols/${id}.svg`,
});
const pdf = compilePdf({
  source,
  files: {/* every path in assets and symbols */},
});
```

- `renderTypst` produces a Typst document that imports a template. All content is emitted as Typst string literals, so text can never be read as Typst markup or code.
- `CompileInput.creationTimestamp` (whole seconds since the epoch) is the time the PDF says it was made: its creation and modification dates and the document ID derived from them, when the document has a date (`date: auto`, e.g. a repository template's). Left out, the compiler uses the time of rendering. The API passes the commit time of the content it renders, so the same commit (a release tag) always gives the same bytes; the generated document itself sets `date: none` (below).
- `compilePdf` compiles through the bundled Typst compiler in a child process and blocks until it is done; no Typst installation is needed. Every PDF is tagged and conforms to PDF/UA-1 unless `standard: 'none'` (see "Accessibility"). Servers should use `compilePdfInWorker`, which compiles on a pool of long-lived worker processes with a timeout and a concurrency limit. A compilation is `interactive` (the default) or `background` (`priority`, #497): a waiting interactive one starts before every waiting background one, so bulk work never holds up a reader. An interactive compilation's `timeoutMs` covers its wait and its compile; a background one's covers its compile only, from when a worker starts it, and it waits at most `waitMs` (default `timeoutMs`), then fails with `TypstTimeoutError` whose `queued` is true. Aborting its `raise` signal while it waits makes it interactive (a reader asked for the same PDF): it moves ahead of the background work, and its deadline from then on is an interactive one's. `defaultPoolSize()` is the pool's size when none is configured.
- Each compilation runs in an empty temporary workspace, in a process that has no packages and no network; documents and templates cannot read host files ("What a template can reach").
- A `TypstCompileError`'s `diagnostics` name files from the project root (`/main.typ`, `/template.typ`, `/assets/…`), never by the server's temporary path.
- Only cross-reference targets get anchors. Links without their own text use the target section's title.
- A `link` mark becomes `#link(...)` only for an address the content model's `isLinkHref` takes (absolute http, https or mailto); any other keeps its text without a link.
- Modules that fell back to the source language are typeset in that language (hyphenation, quotes).
- **QR codes** (#450): `qrCodeMatrix(text)` and `qrCodeSvg(text)` make a QR code here, without any network call (`qrcode-generator`, MIT): byte mode, error correction Q (`QR_ERROR_CORRECTION`), a quiet zone of four modules (`QR_QUIET_ZONE`), printable ASCII only and at most `MAX_QR_TEXT` characters (anything else is a `RangeError`, never a wrong code). `RenderOptions.qrCode` (`{ path, url, placement }`) prints one: `path` the SVG's file among the compile's files, `url` what it holds, printed under it and its alt text. `title-page` puts it on the title page (the template reads `document-info("qr")`), `back-cover` on a last page of its own (the template's `qr-code(path:, url:)`, or a plain fallback defined only in documents that print one). With a page design (#391), each preset's title page sets it at the foot, at the end of the line, beside a `footer` region narrowed by the block's measured width, address included (`title-qr`, `foot-width`); `back-cover` goes on the design's own back page instead (`sys.inputs`, `QR_INPUT`), which it makes when the design has none, and which sets the state `QR_PRINTED`. A repository's own template that ignores the input still gets the code on a page of its own: that page follows only when nothing set the state. The address under the code is set left to right in a right-to-left manual too.

## Templates

`DEFAULT_TEMPLATE` is an A4 layout in the product's design: the theme's fonts, colours and radius (below), the HTML preview's block styles (`@openfolia/render-html`'s stylesheet) adapted for print. It has a title page (a logo slot: branding's logo, else the default brand's mark; the title, the variant, the language, and the release and date when known), a table of contents, numbered headings on the preview's scale (2em, 1.5em, 1.25em, a test holds it), running heads and page numbers in the muted foreground, tables with the preview's tinted header row and borders, steps numbered in filled circles, and ANSI Z535-style safety notices (signal word on the fixed safety colour, framed and tinted body, the symbols' artwork; see Labels). To apply a corporate design, pass your own `template` to `compilePdf`. It must define the functions the generated document uses: `manual`, `anchor`, `safety`, `admonition`, `procedure`, `ui`, `code-span`, `kbd`, `xref`, `unconverted`, `attachment`, `header-cell`, `faq`, `term`, `glossary-entry`, `callout-image` and `callout-ref` (the last seven optional, see below), and keep to what PDF/UA-1 needs ("Accessibility").

- **`safety(severity:, hazard:, symbols:, body)`**: `symbols` holds one file path per symbol the notice names, in order. A symbol without artwork (`symbolPath` gives `undefined`) keeps its place as `openfolia/missing-symbol.svg`, a neutral grey warning sign the compiler provides, never a coloured placeholder; so a template shows every entry with `image(…)` as before.
- **`attachment(name:, file-name:, media-type:, size:, description:)`**: a PDF cannot carry the file, so the template prints the attachment's name, file name, media type and size (already formatted in the manual's language by `formatFileSize`) and its description (`none` when it has none or an empty one), with the note that the file is downloaded from the online version (labels `attachment` and `attachmentNote`). All values are string literals; the file is never embedded in the PDF. The default template frames it as the preview does. A template without `attachment` (one written before it was part of the contract, such as a repository's `templates/manual.typ`) keeps working: the generated document defines a plain box of built-in functions before importing the template, and the template's own `attachment` replaces it.
- **`header-cell(..args, body)`**: every cell of a table's header row (`args` the cell's `colspan` and `rowspan`), inside Typst's `table.header`, which tags them as header cells. It returns a `table.cell(..args, …)`; the default template gives it the preview's tint and semibold text. A table must not be styled by rebuilding it in a `show table` rule: the rebuilt table nests in the original's tags, which PDF/UA-1 refuses. A template without `header-cell` gets a plain cell (the generated document defines one before importing the template, as for `attachment`).
- **`faq(question:, body)`**: an FAQ entry, its question (content) and its answer (`body`, the answer's blocks). The default template prints the question in bold, kept with its answer on the page (`sticky`), then the answer. A template without `faq` gets a plain bold question over the answer (the generated document defines one before importing the template, as for `attachment`).
- **`term(target, body)`** (#245): a term link, `target` the label of its glossary entry (`"_term-<id>"`) when the manual has a glossary, else `none`. The default template underlines the term with dots in the muted foreground (keeping the text's colour: its `show link` rule leaves links to `_term-…` labels alone) and links it to the entry. A term link whose term the manual has not (`ResolvedManual.terms`) is plain text. A template without `term` gets a plain link (the generated document defines one before importing the template, as for `attachment`).
- **The glossary** (`glossary: true` in the manifest, and at least one linked term): after the last module, an unnumbered level-1 heading with the `glossary` label, then per term, alphabetical as resolving sorted them, its anchor (`#anchor("_term-<id>")`, the target of its links) and **`glossary-entry(term:, body)`**: the preferred variant (a string) and the definition (content, empty when it has none). A term without a translation in the manual's language is set in the source language (`set text(lang: …)`). The default template prints the term in semibold, kept with its definition, which is indented below it; a template without `glossary-entry` gets a bold term over its definition.
- **Image callouts** (#546): an image with callouts is drawn by **`callout-image(path:, alt:, width:, markers:, legend:, placement:)`** (in a `figure(kind: image, …)` when it has a title): `path` and `alt` as for `image`, `width` the block's percentage or `auto`; `markers` one dictionary per callout the variant shows, in number order, `(n:, x:, y:, label:, style:)`: its number, its anchor from 0 to 1 across and down the image, its label point (`(x:, y:)`, or `none`: the marker sits on the anchor) and its configured style (`""` for none); `legend` `(n:, body:, at:)` per callout, `body` its legend text as content, `at` where a cut-off entry is reported (`callouts.<module>.<image>.<callout>`, optional); `placement` the image's `calloutLegend`, `"below"`, `"beside"` or `"none"`. The renderer formats every number itself (coordinates with four places, clamped to 0–1; a number that is not a whole number from 1 is `none`) and writes every text as a string literal. The default template measures the image at the width it is laid out at (`layout`, `measure`), so the markers sit right at any scale, and places the drawing from the image's top left corner (`place(top + left, …)`): a leader line from the anchor (with a dot on it) to the label, then a filled circle with the number at the label, or at the anchor without one, as `pdf.artifact` (the legend says what they do, so PDF/UA readers skip them; with `none` a reader gets no list of the callouts, a known gap). These are image coordinates, never mirrored in right-to-left text. The legend is an `enum` numbered in the marker's style (`callout-legend`), directly under the image (above the caption), where it only wraps, or `beside` it in a grid (the image at most 60 % of the line, whatever its width), which follows the text's direction: the legend at the end of the line, so on the left in Arabic. **Beside, the legend never grows past the image's height** (#548, `callout-legend-beside`): it wraps (hyphenated), then shrinks in half points down to the smallest size (`RenderOptions.calloutLabelMinSize`, the configuration's `pdf.calloutLabelMinSize`, 4 to 12 pt, default 6, passed as `sys.inputs` `openfolia-callout-min-size` only to a document with such a legend), and what still does not fit is cut off at the image's height, each entry cut (from the first that ends below it) reported as a `callout-label-overflow` layout warning (`at` its entry's `at`), as a page design's overflow is ("Page designs", "Overflow"). This realises #498's "label overflow": a callout's label on the picture holds only its number, so the legend beside it is the text with a bounded space. A template's own `callout-image` that ignores `at` reports nothing. `none` draws the markers only. **`callout-ref(n)`** is a reference in the text: the number in the marker's style on the line, and `none` (a callout the variant does not show, already a check finding) a muted `?`. The colours are the tokens' `primary` and `primary-foreground` (`muted` and `muted-foreground` for `?`), passed as `colours:`; a page design draws them in its primary colour. A document with callouts defines both functions before importing the template (as for `attachment`, over `/tokens.typ`), so a template without them keeps working, and every style is drawn as the default circle unless a template draws `style` itself. The image's path is read from the project root, so a template in a folder of its own finds it.
- **A page break** needs nothing from the template: it is Typst's own `#pagebreak(weak: true)` (weak, so it never makes an empty page, as the default template's own break before a top-level heading), written only directly in a module or a section. One a module reference brought into a list, a table or a notice is left out, since Typst refuses a page break inside a container.
- **A step's images** stand in its step's body, under its text: indented with the step, and the numbering goes on. A step whose first block is an image has its text in a `#block(sticky: true)`, so the text is never left at a page's foot with its picture overleaf: where the picture does not fit in the space left, the text goes to the next page with it.
- **The title page's data** is set, after the template's `manual` show rule, in the Typst state `"openfolia-document"`: a dictionary with `language` (the manual's language in its own name, "Deutsch"), `variant` (the `subtitle` option), `release` and `date` (the options of the same name; the API passes neither yet, so its PDFs show the language and variant only), each a string literal or `none`. A template reads them with `context state("openfolia-document", (:)).final().at(key, default: none)`; `logo` is read the same way and set by branding (#169): a file path the document's `files` holds. Without one the default template shows the default brand's mark, `openfolia/logo.svg`, which the compiler provides from `@openfolia/theme` (`brand/openfolia-mark-color-light.svg`, read with the theme, like the fonts). A template that ignores the state keeps working.
- **The producer.** Every PDF names OpenFolia as its producer (`PDF_PRODUCER`), in the document information dictionary (`/Producer`) and in the XMP metadata (`pdf:Producer`); Typst stays its `Creator`. The compiler has no option for it, so `compilePdf` and `compilePdfInWorker` append it as an incremental update (`pdf-producer.ts`): the Info and metadata objects again, a cross-reference section for those two and a trailer pointing back at Typst's (`/Prev`). Nothing Typst wrote moves, so the structure tree, the document ID and the same-input-same-bytes rule hold. Only Typst's layout is read (one classic cross-reference table, an unfiltered metadata stream, no encryption); any other PDF is returned unchanged, and a test holds that Typst's output gets the producer, so a compiler upgrade that changes the layout fails the tests, never a PDF.

### Page designs

A manual's page design (#391; the content model's README, "Page designs") is laid out by a **preset template**: `designTemplate(design.preset)` (`PRESET_TEMPLATES`: `classic`, `image-led`, `minimal`) gives the template to pass to `compilePdf`. Each is a short Typst file over the **design layer** (`openfolia/design.typ`, the compiler's own), which imports the default template (`openfolia/default.typ`, `DEFAULT_TEMPLATE` itself) and changes only what the design sets, so every block keeps the default template's style.

```ts
const { source, assets, symbols, fonts, inputs } = renderTypst(manual, {
  design, // resolvePageDesign(…).design
  symbolPath: (id) => `symbols/${id}.svg`,
});
const { pdf, warnings } = await compilePdfReportInWorker({
  source,
  template: designTemplate(design.preset),
  files: {/* assets and symbols, as above */},
  fonts: [/* the files in `fonts` */],
  inputs,
});
```

- **Data, never code.** The design's settings reach the template as JSON in `sys.inputs` (`RenderResult.inputs`, key `openfolia-design`; `CompileInput.inputs`), which the template parses with Typst's `json()`: values only. `designData` checks each first (colours `#rrggbb`, numbers in their ranges, options from their lists, a website the model's `isLinkHref` takes, file paths from `assetPath`), so even a design that skipped validation never becomes markup. The design's texts (each region's blocks, the running header's and footer's places) are content: `renderTypst` writes them with the block rendering every module uses (string literals only; a region's heading, #393, as `heading(numbering: none, outlined: false, bookmarked: false)`, which the layer sets at the second level's size and never breaks the page before) into the state `"openfolia-design"` (`(regions: (…), header: (default: (left: (…), …), first: …, even: …), footer: …)`), a running place as pieces: content, or `(field: "page" | "page-count" | "chapter")` for a page placeholder, which the layer fills in on each page. Without a design the document is as before: no state, no inputs.
- **Title page** (reading order: the title first, what stands above it placed there after it). **classic**: the logo, the `above-title` region, the title, a rule in the accent colour, the data fields, the cover image when there is one (6.5 cm high, all of it shown), `below-fields`, `footer` at the foot. **image-led**: the cover image across the top half, the title, fields and `band` region on a band of the primary colour, `footer` at the foot; without a cover image the band starts at the top (below the logo, its dark version), with no empty box. **minimal**: title and fields low on the page, the cover image above them when there is one, `footer` at the foot. The cover image is the manual's own for the variant, else the manual's, else the design's (#394, `resolvePageDesign`). The title keeps to two lines by shrinking from 28 pt (24 pt for minimal) down to 18 pt (16 pt), then wraps. The logo has the manufacturer's name as its alternative text (else it is an artifact), the cover image its own (none: an artifact); without a design logo, branding's logo (`openfolia-document`'s `logo`), else none.
- **Inner pages**: page size (A4, US Letter or A5, portrait; `paper`) and margins (mirrored when double-sided), body font, size, line height, paragraph spacing (on top of the line gap) and columns (the contents stay in one); headings numbered per level (`decimal` 1.2.3, or `none`), sized from `TYPE_SCALE`, in the design's colour role, with or without a page break before level 1; tables with the header tinted from the primary colour, borders `none`, `horizontal` or `grid`, zebra rows; steps in a filled circle of the primary colour or as a plain number; notes tinted or framed in their colour; links in the primary colour. The design's fonts (only those whose embedding the design confirms) come first, Geist after them.
- **Safety notices** by the design's standard, always in the standard's own colours (the theme's fixed safety colours), never the design's: `ansi-z535`, the default template's signal word panel on top; `iso-3864` (ISO 3864 / EN 82079-1), the safety sign beside the text (the notice's symbols, else the general warning sign; NOTICE has none), the signal word on its colour above the hazard. **Kept whole on a page** (#668): a message that does not fit the rest of a page starts on the next. One taller than a whole page (a column, with two columns) could never be kept whole, so it breaks across pages instead of running off the page, and is reported (`safety-message-split`, below). The generated document marks each safety message of a designed manual just before it with its module and block (`#metadata("safety.<module>.<block>")<openfolia-safety-at>`, `SAFETY_AT_LABEL`), which the layer reads back for that warning; the default template's `safety` takes `breakable:` (default `false`) for it, and a document without a design is unchanged.
- **Running header and footer**: three places (left, centre, right), from the second page on: the `first` set on the first content page (where the body starts, after the contents), the `even` set on even pages when double-sided, `default` elsewhere; none on the title and back pages. Each place keeps to one line: it shrinks from 7.5 pt to 6 pt, then is cut with an ellipsis.
- **Back page**: when the design has one (or text for the `back` or `back-footer` regions), by its `position` (#395): `last`, after the last page, on an even page when double-sided; `inside-cover`, right after the title page (its back, when double-sided), before the contents. It holds the `back` region, the manufacturer (the configuration's: name, address, contact, website as a link), document number and date, copyright, `back-footer` at the foot. A `back-cover` QR code (`delivery.pdfQrCode`) stays on the document's last page when the back page is inside the cover.
- **Overflow** is clipped and reported: a region taller than its slot is cut off (`page-design-overflow`, `at` `regions.<slot>`), a running place still too wide at 6 pt is shortened (`running-head-truncated`, `at` `header.<first|even|default>.<place>`, `text` the whole text); a callout legend beside its image is cut off at the image's height (`callout-label-overflow`, `at` `callouts.<module>.<image>.<callout>`, also without a design, #548); a safety message taller than a page breaks across pages (`safety-message-split`, `at` `safety.<module>.<block>`, `text` its hazard, #668). The compiler reads them only from a designed document or one with such a legend. The layer marks each as `metadata` labelled `<openfolia-warning>`; the compiler reads them back (`compilePdfReport`, `compilePdfReportInWorker`: `warnings`, `LayoutWarning`), keeps only well-formed ones and merges them per code and place (the first page, how many pages). `compilePdf` and `compilePdfInWorker` return the PDF alone, as before.
- A repository's own template can read the same data (`sys.inputs.at("openfolia-design")`, the `"openfolia-design"` state) or ignore it; `page-field(key)` is defined for it (page number and count).

### Own templates (#396)

A page design may name an organisation's own template (`template: <id>` in the design, the content model's README) in place of its preset's: a folder of the content repository, `templates/<id>/`, whose entry file is `manual.typ`. The preset still decides the title page's regions (which the screen offers); the template decides the layout.

```ts
const own = repositoryTemplate(id, files); // files: by path in the folder, as bytes
const { source, inputs } = renderTypst(manual, {
  design,
  templatePath: own.templatePath,
});
await compilePdfReportInWorker({
  source,
  inputs,
  files: { ...assets, ...own.files },
});
```

- **The contract** is the one above ("Templates"): `manual.typ` defines `manual` (a show rule over the whole document), `anchor`, `safety`, `admonition`, `procedure`, `ui`, `code-span`, `kbd`, `xref` and `unconverted`, and may define the optional ones (`attachment`, `header-cell`, `faq`, `term`, `glossary-entry`, `callout-image`, `callout-ref`). It reads the design's settings from `sys.inputs.at("openfolia-design")` (JSON) and its texts from the `"openfolia-design"` state, and keeps to PDF/UA-1 ("Accessibility"). The generated document imports it as `/templates/<id>/manual.typ` (`RenderOptions.templatePath`), so its relative imports and reads (`#import "parts.typ"`, `#image("logo.svg", alt: …)`) find the folder's own files.
- **The example template** (`EXAMPLE_TEMPLATE`, by path in its folder; `exampleTemplateFiles()` as bytes) is the complete starting point: the classic preset as files of its own. `manual.typ` is the classic title page over `design.typ` (the page design layer) over `default.typ` (the default template's block styles). Copied into `templates/<id>/`, it renders the same PDF as the classic preset, byte for byte: `own-template.spec.ts` compares every page's image at 600 px and the PDF's bytes, which also holds the example to the preset whenever either changes. `SAMPLE_TEMPLATES` adds `broken` (an error on its last line, `SAMPLE_BROKEN_LINE`) for the sample content.
- **Its folder only.** `repositoryTemplate` maps the folder's files at their repository paths (`templates/<id>/…`) and nothing else of the repository: not another template, not a module, not `openfolia.yaml`. It refuses (`TemplateFolderError`) an ID that is no slug, a path that leaves the folder, no `manual.typ`, more than `MAX_TEMPLATE_FILES` (200) files or more than `MAX_TEMPLATE_BYTES` (16 MiB) in all (the content repository reads only regular files, never a symbolic link, and checks the caps from the listing before reading a file).
- **Where it fails.** `templateProblems(error.diagnostics)` gives each error of a `TypstCompileError` with its file (the repository path, `main.typ` for the generated document), line and column (1-based), message, and the calls that led there (`trace`), at most `MAX_TEMPLATE_PROBLEMS`; no host path is in them.
- **The probe.** `templateProbe(lang)` is a small manual that calls every function of the contract (each inline mark, a cross-reference, every safety severity and admonition, steps, a list, a table with a header row, a section, an FAQ entry), for checking a template without a manual of the project's: the API compiles it for a design a change set changes.
- **Right to left.** Code in a template's header, footer or title page (`raw`, `code-span`) is set left to right in a right-to-left manual, as the generated document's own code is (a `show raw` rule before the template's `manual` rule).

### What a template can reach

A template (the default one, a repository's `templates/manual.typ` or a design's own `templates/<id>/manual.typ`) and the generated document see one Typst project, the compilation's workspace, and nothing of the host:

- **Files:** only those the compilation maps in memory: `main.typ` (the generated document), `template.typ`, `tokens.typ`, the compiler's own files under `openfolia/` (the missing-symbol sign, the default logo, the default template and the page design layer) and the `files` the caller passes (the manual's images and symbols, the design's assets, an own template's folder). Paths are read from the project root, `/` (`#image("/assets/…")`); a path outside it (`../`, an absolute host path) is refused by Typst, and a missing file is "file not found". The workspace itself is an empty private (0700) directory, checked before every compilation (`assertSafeWorkspace`), so nothing else can be planted there.
- **Typst packages:** none. `#import "@preview/…"` and `@local/…`, in the document or the template, however the name is built, fail with "Typst packages cannot be imported" (`PACKAGE_REFUSED`). The compiler (typst-ts 0.7) has no option for it: it looks packages up in the home directory's cache and data folders and downloads missing `@preview` ones from the package registry. So every compilation runs in a child process whose environment is `sandboxEnv` and nothing else: its home (and `XDG_CACHE_HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`) is a folder inside the pool's private directory that never exists, and its `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` are `BLOCKED_PROXY`, port 0 on the loopback interface, which no process can listen on, so a download fails at once without a request leaving the machine (and without a DNS lookup: the proxy is an address). The child inherits none of the server's environment (no secrets, no `NODE_OPTIONS`), only `TZ`. Linux and macOS find a user's folders through these variables; on Windows the compiler finds them another way, so there compiling refuses to start (`sandboxEnv` throws) rather than run without the sandbox. The child also starts in the pool's private directory, not the server's working directory.
- **Fonts:** the theme's (`fontDirs`), `CompileInput.fonts`, Typst's embedded ones and the system's installed fonts, not the user's, whose folders are under the empty home (none on a bare server; font data only, embedded into the PDF where a document uses it).
- **Nothing else:** Typst has no access to the network, environment variables, the clock beyond `datetime.today()`, or other processes; WebAssembly plugins (`plugin(…)`) can be loaded only from the files above and run in Typst's own sandbox.

### Memory

**One compiler per worker** (#436). Every `NodeCompiler.create` keeps memory until its process ends (typst-ts 0.7: whether or not V8 collects its objects), so a worker keeps one compiler from job to job (`CompilerCache`, `compile-core.ts`). It makes a new one only for a job with another font set (`CompileInput.fonts`, a page design's: fonts are given to a compiler when it is made; the key is a digest of every font's bytes and family, the font directories and the workspace) and after a job that did not end well (a Typst error, a refused export, anything thrown); a job that times out or passes its memory limit ends the process, its compiler with it.

- **Nothing of a job reaches the next.** Every file and source is unmapped (`resetShadow`) before and after each job, so an image, a symbol or an own template's file (`templates/<id>/…`) of the job before is "file not found" at the same path; `sys.inputs` go with each compilation (empty ones too), never with the compiler; and Typst's memoization, keyed by what a compilation read and evicted after each job as before, never hands one job's results to another (`compiler-cache.spec.ts`, `compiler-reuse.spec.ts`).
- **The same input, the same bytes** (#328): after any other jobs on the worker, a manual's PDF is byte for byte the one a new compiler makes.
- **Measured** (`scripts/worker-memory.mjs`: one worker, 300 compilations one after another, a resident-memory sample after each, nice'd on a quiet macOS machine, typst-ts 0.7.0; a test document of 30 sections of running text, and a one-line one):

  | resident memory of the worker                         | 30 sections       | one line          |
  | ----------------------------------------------------- | ----------------- | ----------------- |
  | a new compiler per job (before #436): first job, peak | 109 MB, 485 MB    | 96 MB, 466 MB     |
  | one compiler reused: first job, peak                  | 110 MB, 126 MB    | 97 MB, 103 MB     |
  | growth per job to the peak                            | 1.26 MB → 0.05 MB | 1.24 MB → 0.02 MB |

  Resident memory moves (macOS compresses idle pages): the issue's earlier runs (#436, in one process) measured 4–7 MB a job for a new compiler and 0.3–3 MB for a reused one. Either way, a reused compiler costs a fraction of a new one.

- **Replaced** after `jobsPerWorker` jobs (default `DEFAULT_JOBS_PER_WORKER`, 500, up from 50: a few tens of MB of growth at the rate above) or once it has made `COMPILERS_PER_WORKER` (50) compilers, so jobs that each need a new compiler (each with fonts of their own, or each failing, thrown errors included) are bounded as every job was before (about 450 MB for 50 compilers). Jobs on a reused compiler add their own growth on top: here about 0.05 MB a job (some 25 MB over 500); the issue's earlier figure of up to 3 MB a job would be some 1.5 GB at worst, which the memory limit below still stops, so `jobsPerWorker` is the setting to lower if a deployment measures more. Starting one costs about 100 ms.

**A limit per compilation** (#396): a template is a program, and one can ask for any amount of memory (`range(100000000)`). Each compiling process (a pool worker, or the one `compilePdfReport` starts) watches its own resident memory from a worker thread every 20 ms, and past the limit (`PoolOptions.memoryLimitMb`, `WorkerOptions.memoryLimitMb`; default `DEFAULT_MEMORY_LIMIT_MB`, 2048, at least 256) writes a marker into the pool's private directory and kills itself. The job fails with `TypstMemoryError` (the API answers 422 `render-memory-exceeded`) and the pool starts another worker; the server's own memory is never at stake. The thread runs beside the compiler, which holds the main thread while it compiles, so a compilation that allocates quickly can pass the limit by what it allocates in 20 ms before it is stopped. **Time** is limited as before: `timeoutMs` kills the worker (an endless loop is `TypstTimeoutError`).

### Accessibility

Every PDF is a tagged PDF that declares **PDF/UA-1** (`CompileInput.standard`, default `ua-1` as `DEFAULT_PDF_STANDARD` in `@openfolia/content-model`; the API passes the configuration's `pdf.standard`). The generated document gives what PDF/UA needs: the manual's title (`set document(title: …, date: none)`, before the template, so a template need not set it; no date, since PDF/UA metadata would carry the time of rendering and a PDF from a release tag must be the same every time) and language (`set text(lang: …)`, a fallback module in its own language); headings as `heading` with their levels (a group level 1, a module one deeper, its sections one deeper each); images with their alt text (`image(…, alt: …)`, required by the model) and their caption as a figure; table header rows as `table.header`; lists as `list` and `enum`; cross-references and the table of contents as links. The default template marks decoration as artifacts (`pdf.artifact`), which screen readers skip: the safety symbols and the alert triangle beside the signal word (the signal word and hazard are the text), and the logo. Running heads and page numbers are artifacts by Typst's own rule.

- **Refused, never downgraded.** When Typst cannot export the document under PDF/UA-1 (an image without alt text, a heading without text, a heading level skipped, a character no font can show, a template image neither described nor an artifact), compiling fails with `TypstAccessibilityError`, `problems` holding Typst's messages and hints (`{ message, hints }`, safe to show to the author; the API answers 422 `pdf-accessibility`), and `warnings` what the layout could not fit (as `compilePdfReport`'s: the document is laid out before the export refuses it, #554). The compiler gives an export's diagnostics only as text: `standardProblems` reads them; a refusal it cannot read stays an internal error (logged, never shown). `standard: 'none'` makes a plain PDF (still tagged as far as Typst tags by default, never refused for accessibility). Page images (`compilePagePngInWorker`) ignore the standard.
- **Fonts.** A character no loaded font has is refused (it would show as a box no screen reader can read): Geist covers Latin and Cyrillic, Noto Sans Arabic and Noto Sans Hebrew those scripts, Typst's built-in fonts little more, so a manual in another script (CJK, Thai, …) needs a template naming a font that covers it, or `pdf.standard: none`.
- **A template written before #58** (a copy of the old default template in a repository's `templates/manual.typ`) is refused under PDF/UA-1 until it is brought up to date: its safety symbols are images without alt text, its `show table: header-table` rule rebuilds tables, and its contents' title is contextual. Every PDF then answers 422 `pdf-accessibility`, and every manual's checks show it; bring the template up to the current default (below), or set `pdf.standard: none` meanwhile.
- **A custom template** must keep to it too: a `document` title and text language are set for it, but every `image` it adds needs `alt:` or `pdf.artifact(…)`, a heading's title must be text, not contextual content (read state around the element: `context outline(title: state(…).final()…)`, as the default template does for the contents' title), and tables are styled through `header-cell` and set rules, never rebuilt in a show rule.
- **Tests** read the PDF (`render.spec.ts`, "PDF/UA-1"; the API's `tests/pdf-ua.e2e.spec.ts`): the structure tree, headings, figures with their `/Alt`, `TH` header cells, lists, links, the contents, `/Lang`, the title with `DisplayDocTitle`, and `pdfuaid:part` 1 in the metadata.
- **veraPDF, locally** (not in CI: it needs Java). Install the veraPDF CLI (`brew install verapdf`, or the installer from verapdf.org), start the API (`pnpm nx run api:serve-local`; `$TOKEN` is the token `api:setup-local` printed, `$PORT` the API's port), and validate a manual's PDF against the PDF/UA-1 profile:

  ```sh
  curl -s -H "Authorization: Bearer $TOKEN" -o /tmp/manual.pdf \
    "http://127.0.0.1:$PORT/manuals/operating/variants/model=large/en/pdf"
  verapdf --flavour ua1 --format text /tmp/manual.pdf
  ```

  `PASS` means veraPDF's machine checks hold; PDF/UA also has checks only a person can make (a meaningful reading order, alt texts that describe), which no tool replaces.

### Theme: tokens and fonts

The design comes from `@openfolia/theme` (`frontend/theme`), read when the first PDF is compiled, so the PDF follows the theme and nothing is copied by hand:

- **Tokens.** Every compilation gets `tokens.typ` next to the template: the light values of `theme.css`'s custom properties as one Typst dictionary, `theme`, keyed by the CSS names without `--` (`theme.foreground`, `theme.muted-foreground`, `theme.border`, `theme.info-muted`, `theme.safety-danger`, `theme.safety-danger-foreground`, `theme.radius`, `theme.font-sans`, `theme.font-mono`, …). Colours keep their `oklch` values; `rem` becomes `em` (the root size is the body text size in print); a font stack keeps its named families. Only the light theme applies to print; the safety colours are the theme's fixed ISO 3864 / ANSI Z535 ones. Any template, a custom one too, can `#import "/tokens.typ": theme` (the leading `/` is the workspace root, so it works from a template in a subdirectory too). A token the conversion does not know fails the tests and every PDF, so none goes missing silently. `main.typ`, `template.typ`, `tokens.typ` and everything under `openfolia/` are the compiler's own: `files` cannot replace them.
- **Fonts.** Geist and Geist Mono as TTF (Typst cannot read WOFF2), in `frontend/theme/src/fonts/ttf/` with their licence (SIL Open Font License 1.1, `LICENSE.txt`), from the same release as the theme's WOFF2 files. Every compilation, on the main thread or on a worker, loads that directory by path; `CompileInput.fonts` adds more. `CompileInput.fonts` (a page design's fonts) may be TrueType, OpenType, WOFF or WOFF2: the compiling child decodes WOFF (zlib) and WOFF2 (brotli, its glyf, loca and hmtx transforms undone) to TrueType/OpenType (`sfntFromFontFile`, at most 64 MiB a font and 256 MiB together), and a font that does not decode is left out, so the text falls back to the default fonts, as Typst does for a font file it cannot read. A design's font comes with a family (`{ data, family }`, `RenderResult.fonts`: `designFontFamily(role)`, `openfolia-body-font` or `openfolia-heading-font`) and is loaded under it (`sfntWithFamily`: name IDs 1 and 16 replaced, 21 left out, the PostScript name, `OS/2` and `head` kept), since Typst knows a font by its name ID 1 with style words such as Condensed or Black cut off, which is often not the family the design names; the design data (`design.fonts.body`, `design.fonts.heading`) names the role's family, so the faces are found whatever the files call themselves; a repository's own template uses those names too. Not yet: a font whose PostScript name Typst knows from its own list of exceptions (some older static families) keeps Typst's family for it and falls back. They are loaded before the theme's directory: typst-ts 0.7.0 aborts the child on memory fonts added after a font directory. A deployment has to ship `@openfolia/theme` with the API (its `src/fonts/ttf/` included); a missing theme package or font file fails the first PDF instead of falling back to other fonts. Noto Sans Arabic and Noto Sans Hebrew (Regular, Medium, SemiBold, Bold; SIL Open Font License 1.1, `LICENSE-Noto.txt`) sit beside them, after Geist in the theme's font stack: Latin text, numbers and code keep Geist, Arabic and Hebrew letters take Noto. Geist covers Latin and Cyrillic: Greek, CJK and other scripts fall back to Typst's built-in fonts or the host's (none on a bare server), so a manual in such a language needs a template naming a font that covers it.
- **Direction** (#458). Every `set text` the renderer writes (the document, each module, each glossary term) names its language's `dir` (`directionOf`: the script's or `languages.direction`), so a right-to-left manual sets its pages, header and footer, lists, grids and tables mirrored, and a module that fell back to the source language stays left to right inside it. A column's `left` and `right` are `start` and `end`; the template's glossary indents from the start of the line. Mixed-direction text (a Latin name, a number, code in Arabic) is ordered by Typst's bidi algorithm.

### Labels

The fixed texts around the content follow the **manual's** language (never the reader's interface language): the safety signal words (`danger`, `warning`, `caution`, `notice`), the admonition captions (`note`, `tip`, `important`), the table of contents title (`contents`), the figure and table captions (`figure`, `table`) the marker for unconverted content (`unconverted`), the attachment label and note (`attachment`, `attachmentNote`), and the glossary's title (`glossary`).

- They are configuration: `DEFAULT_OUTPUT_LABELS` in `@openfolia/content-model` ships English, German and French, and the project configuration's `outputLabels` (`openfolia.yaml`) overrides any of them per language tag. `renderTypst(manual, { outputLabels: config.outputLabels })` resolves the set for `manual.lang` (exact tag, then its base language, configured before shipped) with English for any missing key; `resolveManual` reports such a gap as a `missing-label` warning, so it shows as an issue, never as a failed PDF.
- The generated document sets them, after the template's `manual` show rule, as a dictionary in the Typst state `"openfolia-labels"` (`#state("openfolia-labels", (:)).update((danger: "GEFAHR", …))`), every value a Typst string literal. A template reads them with `context state("openfolia-labels", (:)).final().at(key)`; `final()` gives the value on the title page and the table of contents too. A template that ignores the state keeps working (it prints its own texts). The default template falls back to English when a document sets none, and sets the outline title and the figure and table supplements from the labels, so it does not depend on Typst's built-in translations.
