# @openfolia/render-html

Renders a resolved manual (from `resolveManual` in `@openfolia/content-model`), or one module of it, to semantic, accessible HTML: the editor's preview and the portal share it. It takes the same input as the PDF renderer (`@openfolia/render-typst`).

```ts
const { manual } = resolveManual({
  manifest,
  variant,
  lang,
  config,
  loadModule,
});
const { html, assets, symbols } = renderManualHtml(manual, {
  assetUrl: (sha256) => `/assets/${sha256}`,
  symbolUrl: (id) => `/symbols/${id}`,
  symbolLabel: (id) => config.safetySymbols.find((s) => s.id === id)?.label,
  outputLabels: config.outputLabels,
  subtitle: 'L-400 · Software 2.3 · EU',
});
const module = renderModuleHtml(manual, 'battery-charging', { assetUrl });
```

```css
@import '@openfolia/theme/theme.css';
@import '@openfolia/render-html/render-html.css';
```

- `renderManualHtml(manual, options)` gives one `<article class="of-content of-manual">`: the title (and `subtitle`), a table of contents (`toc: false` leaves it out), the groups and modules in order. `renderModuleHtml(manual, moduleId, options)` gives one `<article class="of-content of-module">` for the module's first occurrence (`title: false` leaves its title out, for a host that shows it), or `undefined` when the manual has no such entry. To preview a single module, resolve a manifest that lists only it. Both return a fragment (no `<html>` or `<body>`), the image assets it uses (`sha256:…`), the attached files it links (`attachments`) and the safety symbols it shows.
- The input must be resolved: a `variant` or `moduleRef` block throws `HtmlRenderError` (resolving applies the conditions and inlines module references). So does a block, inline or mark type the renderer does not know: every type of the model has a renderer (the switch is exhaustive, ending in `never`, and a test reads the model's schemas, so a new type such as an FAQ block fails to compile, and its test fails, until it has one).
- Headings start at `headingLevel` (default 1: the manual's title is an `<h1>`, groups and top-level modules `<h2>`, sections below them). Below level 6 a heading is an `<h6>` with its real `aria-level`.
- Every block and list item gets its output ID (`module--block`) as its element ID, prefixed with `idPrefix` (default `of-`), so IDs never clash with the host page's IDs or globals; a module's section gets the module ID (once, if it is listed twice). The heading of a module, a section and the glossary gets its own ID under `_h-` (`headingIdOf`: `of-_h-charging`, `of-_h-charging--care`, `of-_h-_glossary`; #784), so a search index such as the portal's Pagefind finds a page's passages by their headings. A module that fell back to the source language carries its own `lang`.
- **Cross-references** are links to those IDs (`#of-basics--lights`); without text of their own they show the target section's title, else the module's. A target that is not part of what is rendered (another module, in `renderModuleHtml`) is plain text (`of-xref--unresolved`), unless `xrefHref({ module, block, id })` returns a link for it, e.g. to another page of the portal.
- **Term links** (`term` marks, #245) show the term the manual resolved (`ResolvedManual.terms`): the text in a `of-term` wrapper, then its definition as a tooltip (`role="tooltip"`, `data-pagefind-ignore`, so a search index keeps the sentence and not the tooltip text; the link's `aria-describedby`, so screen readers announce it), which the stylesheet shows on hover (the tooltip itself hoverable) and on keyboard focus. Where the browser has CSS anchor positioning the tooltip is `position: fixed` and anchored to its term, so no clipping or scrolling ancestor (a table's wrapper, an FAQ sliding open, #891) cuts it off, and it flips above or aside when it would leave the viewport; elsewhere it stays under the term (absolute). A safety notice does not clip (its signal bar rounds its own corners). With a glossary rendered, the text is a link to the term's entry (`#of-_term-<id>`), so it works without JavaScript and without the stylesheet; without one (a single module, a manual without `glossary: true`) it is focusable text. Escape hides a tooltip only where the host runs script: `dismissTermOnEscape(document)` adds `of-term--dismissed` to the term under the pointer or focus until both leave it (the editor's preview does). A term link whose term the manual has not (none, or in neither language) is plain text (`of-term--unresolved`); a definition in the source language (no translation) carries its `lang`.
- **The glossary**: a manual whose manifest says `glossary: true` ends with one (`of-glossary`, titled by the `glossary` output label, listed in the table of contents): a `<dl>` of the terms it links, in the order resolving gives (alphabetical in the manual's language), each its preferred variant in a `<dfn>` and its definition, a space between the two so extracted text (a search index, a copy) never runs them together. Its IDs start with `_` (`_glossary`, `_term-<id>`), which no module's or block's can.
- **The preview** (`preview: { attributeLabel }`, the editor's) shows what readers never see: a page break directly in a module or section as a dashed rule labelled "Page break (PDF)" (one a module reference brought into a list, a table or a notice does nothing in the PDF and shows nothing here either), and a text attribute without a value (a module previewed without a manual) as a chip with its configured label (`attributeLabel(name)`, else the name), titled "Not set for this preview". Without `preview`, the HTML readers get: a page break shows nothing, and an attribute without a value stays `{name}` (`of-attribute--missing`). The preview's two texts follow the manual's language (`PREVIEW_LABELS`: English, German, French; English for any other); they are not output labels, since no output prints them.
- **Image callouts** (#546): an image with callouts is a `of-callouts` wrapper: the picture (`of-callouts__picture`, which takes the image's width) with an SVG over it (`of-callouts__overlay`, `aria-hidden`), and the legend. The SVG has no `viewBox`: every coordinate is a percentage of the picture (`x1="60.00%"`), so it scales with the picture and needs no image size, and the marker's radius is in pixels, so nothing distorts. It draws a leader line from each anchor to its label with a dot at the anchor, and each marker (a filled circle with its number) at its label, or its anchor without one. These are image coordinates, never mirrored in right-to-left text. The legend (`of-callouts__legend`, an `<ol>`) lists the callouts the variant shows in number order, each entry its number in the marker's style (`of-callout-number`) and its text (which wraps, a long word broken and hyphenated by the page's language, never widening the page), under the picture (`of-callouts--below`, the default) or beside it (`of-callouts--beside`, at the end of the line, so the left in right-to-left text; wrapping under it when its column would be narrower than 12em, so it never needs to shrink or be cut off as the PDF's does, #548), or not at all (`of-callouts--none`, the image's `calloutLegend`). The markers repeat the legend, so screen readers read the legend alone; with `none` they get no list of the callouts (a known gap: the text's references then name numbers only). A `calloutRef` prints its callout's number in the marker's style (`of-callout-ref`); one to a callout the variant does not show prints `?`, muted (`of-callout-ref--unresolved`). A callout's `style` is written as `data-callout-style` on its marker when it is a configuration key, for a host stylesheet to draw; this one draws every style as the default circle.
- **Callout highlighting** (#549): a callout's marker, its leader line and anchor dot, its legend entry and every reference to it carry the same key, `data-callout="<image output ID>:<callout ID>"` (written only when both are IDs the model allows). A numbered reference is a link to its image (`<a class="of-callout-ref" href="#of-<image>">`), so it takes the keyboard focus and leads to the picture without script; a `?` reference stays text. The output runs no script: a host page that runs script calls `highlightCallouts(document)`, which gives every part of a callout `of-callout--highlighted` while one of them is under the pointer or holds the focus (the pointer wins), and returns the function that stops it. The stylesheet draws that as a ring around the marker and a thicker leader line, an outline on the entry and the reference (never colour alone; no change of weight, so no text moves), animated only without `prefers-reduced-motion: reduce`. Keys are compared as strings, never put into a selector. The markers take the pointer (`pointer-events: auto`); the legend entries are not in the tab order (they do nothing of their own), the references are. The editor's preview frame, which runs no script, does the same from outside its sandbox; the portal (#44, `frontend/portal`) calls `highlightCallouts`.
- **In the browser:** `@openfolia/render-html/browser` exports only `highlightCallouts` and `dismissTermOnEscape` (with their classes and types), so a page's bundle holds neither the renderer nor the content model.
- **Fixed labels** (safety signal words, admonition captions, "Contents", "Figure", "Table", the unconverted marker) follow the **manual's** language through the same label set as the PDF: `resolveOutputLabels(manual.lang, options.outputLabels)` from `@openfolia/content-model` (see `render-typst`'s README, "Labels"). Figures and tables with a title are numbered in document order ("Figure 1: …"); untitled images get no caption.

- **Offline site** (#59, `offline-site.ts`): the pages of an offline package, a static site that opens from the file system. `offlinePageHtml({ lang, dir, title, root, fragment, pdf?, footer })` wraps a rendered manual (`renderManualHtml`'s `html`, its links relative to the page) in a whole document: a bar back to `index.html` (`of-offline__home`) and to its PDF (`of-offline__pdf`), the fragment in `<main>`, a footer; no script. `offlineIndexHtml({ lang, dir, title, subtitle, manuals, search, footer })` lists every manual and its variants (`of-offline__page`, each with its PDF), with a search (`of-offline__search`, hidden until its script runs) over `search` (`[text, page, context]` in a `<script type="application/json" id="of-search-index">` data block, never run, `<`, `>` and `&` escaped). The search is `OFFLINE_SEARCH_SCRIPT`, to be saved as `assets/search.js` (`OFFLINE_SEARCH_PATH`): it folds case and accents, matches every word, writes its results as text only and links only to `manuals/…`. Both pages link the stylesheets in `OFFLINE_STYLESHEETS` (the theme, its dark values under `prefers-color-scheme: dark`, `render-html.css`, `OFFLINE_SITE_CSS` as `assets/site.css`, on the theme's variables only, its classes under `of-offline`) and carry `offlineContentSecurityPolicy`: `default-src 'none'`, the package's own files only (`'self'`), the index's script file and no inline script. Every text is escaped; a link that is absolute, has a scheme or leaves the package is dropped. The fixed labels ("All manuals", "Search", …) are `offlineLabels(lang)`, English for a language it has none for. `manualHeadings(manual)` lists each module's and section's title with the element ID the rendered manual gives it, for the search.

## Security

The output is safe to insert into a page as HTML, whatever the content holds (valid or not):

- **Escaped by construction.** Markup is written only by the renderer. Every string from the content and from the callbacks goes through one escape (`&`, `<`, `>`, `"`, `'`; a carriage return becomes `&#13;`, so text reads back exactly; a NUL, which HTML cannot carry, becomes U+FFFD) before it reaches text or a quoted attribute. Values that become class names or attributes with meaning (severity, admonition kind, alignment, spans, widths, language tags, directions, the literal's language) are checked against their allowed values first and left out otherwise; widths and spans are numbers the renderer formats itself.
- **Links** (`link` marks, which must also pass the content model's `isLinkHref`: absolute http, https or mailto; `linkHref(address)` may then lead one elsewhere or, with `undefined`, take the link away; and what `xrefHref`, `linkHref`, `assetUrl` and `symbolUrl` return) are allow-listed by `safeUrl`: `http:`, `https:`, `mailto:` or relative (a path, `?query`, `#fragment`). Any other scheme (`javascript:`, `data:`, `vbscript:`, `file:`, …) and any URL with whitespace, control characters or a backslash (which browsers strip or rewrite before reading the scheme) is refused: a refused link keeps its text without the link (`of-link--refused`), a refused image URL leaves the `<img>` without `src`. External links get `rel="noopener noreferrer"`.
- **Images** are only ever linked through the caller's `assetUrl(sha256)` (required), given the 64 hex digits of a valid `sha256:` asset reference: never a path from the content. An invalid reference renders the image without `src`.
- **Attachments** are linked the same way: an `<a href="assetUrl(sha256)" download="<file name>" type="<media type>">` with the name as its text, then the file name, the media type and the size (in the manual's language, `formatFileSize`), and the description below. The `download` attribute only names the file; the download itself is the server's to make safe (`GET /assets/:sha256` sends an attached file with `Content-Disposition: attachment`, `nosniff` and a sandboxing CSP). The `type` is written only when it is a plain media type; an invalid reference leaves the name without a link.
- **Passthrough is refused, never sanitised.** A `passthrough` block (an importer's escape hatch, flagged by validation) shows its raw source escaped, as text, in a box marked "Unconverted content (format)", as the PDF does. It is never interpreted as HTML: there is no HTML-to-model mapping whose output would be trustworthy, an allow-list sanitiser would be a second parser to keep in step with browsers, and content meant to stay belongs in model blocks.
- A property test (`xss.spec.ts`) renders random manuals full of hostile strings (including random callback results and invalid values), parses the output as a browser does, and fails on any element, attribute, URL scheme, style or class the renderer does not write itself; another checks random text reads back unchanged in text and attributes.
- **The callouts' SVG** is written by the renderer alone: `svg`, `line`, `circle`, `g` and `text` elements, coordinates the renderer formats from numbers (a percentage with two decimals, clamped to the picture; a coordinate that is not a finite number is 0), a marker's number as text (a whole number, else `?`), a callout style only when it is a configuration key (`CONFIG_KEY_PATTERN`), and a callout's key (`data-callout`) only when its image's and callout's IDs match the model's ID patterns. The legend is inline content, escaped like any other. The property test checks the SVG's elements and every attribute value against what the renderer writes.
- Inline `style` attributes carry only widths (`width:NN%` on images and table columns). Under a Content Security Policy without `style-src-attr 'unsafe-inline'` they are ignored and the layout falls back to automatic widths; nothing else depends on them. The output has no scripts and no event handlers.

## Styling

`render-html.css` (exported as `@openfolia/render-html/render-html.css`) styles the output on the theme's CSS variables (`@openfolia/theme`, imported first): it writes no colour of its own, so the theme's `.dark` class gives the dark look, and the safety notices use the theme's fixed `--safety-*` colours in both. Every rule is scoped under `.of-content`, so nothing reaches the host page. Tables scroll sideways inside their wrapper, and long words wrap, so the fragment never widens the page.

**Direction** (#458). Every element with a `lang` also carries its `dir` (`directionOf`, from the resolved manual: the language's script or `languages.direction`), so a right-to-left manual, and a left-to-right module inside it, each lay out in their own direction. The stylesheet uses logical properties only (`padding-inline-start`, `inset-inline-start`, `text-align: start`), so lists, notes, tables and the glossary mirror without a rule of their own; a column's `left` and `right` are `start` and `end` (`of-table__cell--right` is `text-align: end`). In right-to-left text, code (inline code, code blocks, keys) is `dir="ltr"`, and UI labels, cross-references, term links and attribute values are isolated (`unicode-bidi: isolate`), so a Latin name, a number or an error code keeps its order inside the sentence.

A step's images (and its other blocks) are inside its `<li>`, after its `of-item__text`: indented with the step, the numbering going on; a step with an image is not broken across printed pages (`break-inside: avoid`).

The class names are stable (a rename is a breaking change for the preview, the portal and custom stylesheets) and all start with `of-`:

## Development

```
nx test render-html
nx run render-html:typecheck
```

Tests: unit tests over a fixture manual using every type (`src/testing/fixture.ts`), snapshots of the sample content repository's manuals (`@openfolia/content-repo/testing`) for every variant and language at each ref, the XSS property tests, and the stylesheet's checks (no colour literals, only the theme's variables, every rule scoped, every class the renderer writes documented in the table above).
