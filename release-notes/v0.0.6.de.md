OpenFolia v0.0.6 ist vor allem ein Umbau im Inneren der API, ohne Änderung an dem, was man sieht
oder was die API antwortet, mit einer Änderung bei der SAML-Anmeldung: Antworten von vielen Adressen
zugleich können die aller anderen nicht mehr verdrängen.

- SAML-Anmeldung: Die Antworten aus einem Netz (IPv4 /24, IPv6 /48) werden nacheinander geprüft,
  sodass ein Netz nie alle SAML-Prüfungen des Servers belegt und eine Antwort von anderswo weiter
  innerhalb des Zeitlimits geprüft wird. Höchstens 8 Antworten eines Netzes und 3 einer Adresse
  warten, bis sie an der Reihe sind; jede weitere wird mit „Der Anmeldedienst ist nicht erreichbar“
  abgelehnt, nicht als fehlgeschlagene Anmeldung gezählt und einmal je Netz protokolliert. Hinter
  einem Reverse Proxy muss CCMS_TRUST_PROXY wie in der Anleitung gesetzt sein, sonst scheint jede
  Antwort aus einem Netz zu kommen. Zur Anleitung:
  https://docs.openfolia.com/de/guide/self-hosting/saml
- Umbau: Jeder Teil der API meldet jetzt seine eigenen Berechtigungen, Webhook-Ereignisse (und wie
  jedes Ereignis entsteht und wer es sehen darf), Audit-Aktionen, Benachrichtigungsarten und
  Einstellungen an, und das Datenbankschema liegt in einer Datei je Teil. Namen der Berechtigungen,
  Rollen, Webhook-Inhalte, Benachrichtigungseinstellungen, Einstellungen, die API und ihr
  OpenAPI-Dokument bleiben gleich.
- Datenbank: Ein Befehl schreibt eine Basis-Migration für eine gewählte Auswahl an Komponenten in
  einen Ordner Ihrer Wahl, für eine neue Datenbank (`pnpm nx run api:db-baseline`,
  backend/api/README.md „Database“). Die bestehenden Migrationen bleiben unverändert, und beim Start
  läuft keine neue.

Upgrade: Nichts zu tun außer dem Üblichen. Legen Sie zuerst ein Backup an und folgen Sie
deploy/README.md#upgrades. Melden sich Personen per SAML über einen Reverse Proxy an, prüfen Sie
CCMS_TRUST_PROXY vor dem Upgrade.
