The MCP server lets AI assistants and agents (Claude Code, Cursor, Claude Desktop, your own) search
and read your **released** documentation over the [Model Context Protocol](https://modelcontextprotocol.io).
It only reads. An assistant sees `main` and the release tags, never a draft, a change set or a
comment, and only what your token's service account may read. It cannot change anything.

To connect a client you need two things: the server's **address** and a **token of your own**.

## The address

The server speaks Streamable HTTP at `/mcp` on the editor's own address:

| Where your OpenFolia runs                  | The MCP address                                                       |
| ------------------------------------------ | --------------------------------------------------------------------- |
| Hosted                                     | `https://<team>.openfolia.com/mcp`                                    |
| Self-hosted, through the editor            | the editor's address plus `/mcp`, e.g. `https://docs.example.com/mcp` |
| Self-hosted, on the same machine, directly | `http://127.0.0.1:3200/mcp` (the MCP port, `OPENFOLIA_MCP_PORT`)      |

The endpoint is **stateless**: every request is one `POST` with one JSON-RPC message, answered with
JSON. There are no sessions and no event stream, so `GET` and `DELETE` answer 405, which MCP clients
expect. Where no MCP server runs, `/mcp` answers 404.

## Your token

Every request carries `Authorization: Bearer <token>`: a **service account token of your own**
(`ccms_sat_…`), whose role holds `content.read` and nothing else. Each person or agent that
connects gets one, so one can be revoked without stopping the others, and each reads within its own
role's scope (languages, module types, audience, facets). A module outside that scope is
`not-found`, exactly like one that does not exist. A token that may do more than read (drafts,
editing, releases) is refused with 403 `token-not-read-only`, so a role given by mistake never
widens what an assistant reads.

### Make a service account and token for MCP

An admin does this in the editor, once for each person or agent that connects. It works the same
hosted and self-hosted, with no provider involved.

1. **A role that may only read.** In **Admin**, open **Roles** and choose **New role**. Name it,
   for example "MCP reader", and tick **content.read** alone. To limit what it reads, set its
   **Scope**: audience levels, languages, module types or facets
   ([Make or change a role](/guide/admin/users-and-roles#make-or-change-a-role)). Choose
   **Create role**.
2. **A service account with that role.** In **Admin**, open **Service accounts** and choose **New
   service account**. Name it after who connects, for example "Claude Code, Jane", and under
   **Roles** choose the role of step 1
   ([Add a service account](/guide/admin/service-accounts#add-a-service-account)).
3. **A token.** In its row, choose **Tokens**, then **Issue token**. Under **What it is for**,
   write "MCP", choose how long it lasts, and choose **Issue**. **Copy the token now**: it is shown
   once ([Issue a token](/guide/admin/service-accounts#issue-a-token)).
4. **Use it as the bearer token** in your client, as the next sections show. Keep it out of shared
   files and chats: anyone who holds it reads what its account reads.

**Revoking it:** **Revoke** beside the token (Admin, Service accounts, **Tokens**). Every read with
it is refused from then on, and the server lets it in no more within a minute; the other callers
go on. Before a token expires, issue a new one and replace it in your client. The token's **Last
used** shows when it read: the API sees each caller's own account.

**Reads are logged per token.** Every read the server makes for you is recorded in the audit log
under your service account, with the token's ID, the API route, the ref and the tool that read
(`mcp/search`, `mcp/read_module`, …; the server's own token checks show as `mcp`). An admin sees
them in **Admin**, **Audit log**, under **Reads**
([Reads of service accounts](/guide/admin/audit-log#reads-of-service-accounts)). What you asked
the assistant, and what the API answered, are never recorded.

## Connect Claude Code

1. **Put the token in an environment variable.** Add this line to your shell's profile
   (`~/.zshrc`, `~/.bashrc`) with an editor rather than typing it, so that the token stays out of
   your shell's history and your project files:

   ```sh
   export OPENFOLIA_MCP_TOKEN='<your token, ccms_sat_…>'
   ```

2. **Add the server.** Your shell fills in the token, and Claude Code stores it in your own
   configuration (`~/.claude.json`):

   ```sh
   claude mcp add --transport http --scope user openfolia https://<team>.openfolia.com/mcp \
     --header "Authorization: Bearer $OPENFOLIA_MCP_TOKEN"
   ```

   `--scope user` makes it available in every project. Leave it out to add it to the current
   project only.

3. **Check it:** `claude mcp list` shows `openfolia` as `✔ Connected`. In a session, `/mcp` lists it
   with its tools. Then ask, for example, "Which manuals are in OpenFolia?": Claude calls
   `list_manuals`.

**For a whole team, in the repository:** a project's `.mcp.json` is shared through Git, so it names
the variable, never the token. Claude Code expands `${…}` in `url` and `headers`, and each person
sets `OPENFOLIA_MCP_TOKEN` themselves:

```json
{
  "mcpServers": {
    "openfolia": {
      "type": "http",
      "url": "https://<team>.openfolia.com/mcp",
      "headers": { "Authorization": "Bearer ${OPENFOLIA_MCP_TOKEN}" }
    }
  }
}
```

## Cursor and other clients that take a URL and headers

Cursor reads `~/.cursor/mcp.json` (for you) or `.cursor/mcp.json` (for one project), and expands
`${env:NAME}` in `url` and `headers`:

```json
{
  "mcpServers": {
    "openfolia": {
      "url": "https://<team>.openfolia.com/mcp",
      "headers": { "Authorization": "Bearer ${env:OPENFOLIA_MCP_TOKEN}" }
    }
  }
}
```

Other clients that connect to a Streamable HTTP server with custom headers take the same two
values: the URL, and the header `Authorization: Bearer <token>`. How each one names the fields and
expands variables is in its own documentation.

## Claude Desktop and other clients that start a local server (stdio)

A client that only starts servers on your machine runs the MCP server itself, over stdio. That
server reads the API directly, so it takes the API's address and your service account token (the
same kind of token as above) as settings:

- `CCMS_MCP_API_URL`: the API, `https://<team>.openfolia.com/api` (self-hosted: the editor's
  address plus `/api`).
- `CCMS_MCP_API_TOKEN`: a service account token (`ccms_sat_…`) whose role holds `content.read`
  alone, made as in [Make a service account and token for
  MCP](#make-a-service-account-and-token-for-mcp). The server refuses a token that may do more.

With Docker, it runs the MCP image of your instance's version. Claude Desktop's configuration file is
`~/Library/Application Support/Claude/claude_desktop_config.json` on macOS and
`%APPDATA%\Claude\claude_desktop_config.json` on Windows:

```json
{
  "mcpServers": {
    "openfolia": {
      "command": "docker",
      "args": [
        "run",
        "-i",
        "--rm",
        "-e",
        "CCMS_MCP_API_URL",
        "-e",
        "CCMS_MCP_API_TOKEN",
        "ghcr.io/<owner>/openfolia/mcp:<version>",
        "node",
        "dist/main.js"
      ],
      "env": {
        "CCMS_MCP_API_URL": "https://<team>.openfolia.com/api",
        "CCMS_MCP_API_TOKEN": "ccms_sat_…"
      }
    }
  }
}
```

From a checkout of the repository (`pnpm nx build mcp`), use `"command": "node"` and
`"args": ["/path/to/checkout/backend/mcp/dist/main.js"]` with the same `env`. The token is then in
that file: keep the file to yourself.

## Check it without a client

```sh
curl -sS -X POST https://<team>.openfolia.com/mcp \
  -H "Authorization: Bearer $OPENFOLIA_MCP_TOKEN" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  --data '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

The answer lists the nine tools. Without the header, it is 401; with a token that may do more
than read, 403 `token-not-read-only`.

## The tools

Every tool is read-only. The [MCP tools and resources reference](/reference/mcp-tools) lists each
with all its arguments, generated from the server's own definitions.

| Tool                                                                    | What it gives                                                                          |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| [`search`](/reference/mcp-tools#search)                                 | up to 20 results with excerpts, filtered by language, type, audience, facets, keywords |
| [`read_module`](/reference/mcp-tools#read_module)                       | one module as Markdown, optionally for a variant, with its metadata                    |
| [`list_manuals`](/reference/mcp-tools#list_manuals)                     | the manuals with their variants, and the configured languages                          |
| [`read_manual`](/reference/mcp-tools#read_manual)                       | a manual for a variant and language as Markdown, in its order                          |
| [`get_chunks`](/reference/mcp-tools#get_chunks)                         | retrieval chunks with their metadata, filtered, or changed since a time                |
| [`list_variants`](/reference/mcp-tools#list_variants)                   | the variant attributes and their values                                                |
| [`list_releases`](/reference/mcp-tools#list_releases)                   | the releases, newest first, and whether one was withdrawn                              |
| [`list_downloads`](/reference/mcp-tools#list_downloads)                 | each product's downloadable files at its latest release                                |
| [`list_download_versions`](/reference/mcp-tools#list_download_versions) | one download's versions across releases                                                |

Lists are paged by `cursor`: an answer's `nextCursor` asks for the next page, and is null after the
last one.

## Resources

Besides the tools, each manual is a resource per variant and language,
`openfolia://manuals/<id>/<variant>/<lang>`, as Markdown (what `read_manual` gives), at `main`.
Clients that show resources (attach a file, say) list them with `resources/list` and read one with
`resources/read`. See [Resources](/reference/mcp-tools#resources) in the reference.

## Which content: `ref`

The content tools take `ref`: `main` (the default, the current released content) or a release tag
from `list_releases`, to read the documentation as it was at that release. A change set's branch, a
commit ID or a maintenance line's branch is refused (`ref-not-released`) before anything is read,
and so is a withdrawn release (`release-withdrawn`).

## Errors

A tool that fails answers with `isError` and a JSON body
`{ "error": { "code", "title", "detail"?, "status"?, "retryAfter"? } }`. `code` is stable: an
assistant (or your own code) can act on it. The ones you meet most:

| Code                                    | What it means                                                        |
| --------------------------------------- | -------------------------------------------------------------------- |
| `not-found`                             | no such module or manual, or one outside the service account's scope |
| `unknown-variant`                       | the manual has no such variant                                       |
| `ref-not-released`, `release-withdrawn` | the `ref` is no released content (see above)                         |
| `token-not-read-only`                   | over stdio: the service account may do more than read (see below)    |
| `busy`                                  | too many calls at once: try again shortly                            |
| `api-unavailable`                       | the server could not reach the API                                   |
| `invalid-cursor`                        | a `cursor` this server did not give                                  |

The full list is in `backend/mcp/README.md` in the repository, the server's own documentation.

## Limits

- One server runs at most **8 tool calls at once** and queues 32 more; past that, `busy`.
- A call has **120 seconds**, waiting included. A client that cancels it frees its place.
- One client address may send **600 requests a minute**; then 429 with `Retry-After`.
- Wrong tokens: after **10 a minute from one address**, or 100 from all addresses together, every
  token that is no service account's gets 429 until the minute ends. A service account token is
  still checked then, unless wrong ones came from its own address 10 times that minute; a caller
  already connected is always served. One address may have 4 token checks under way at once.
- A token is checked with the API when it first connects, and again **once a minute** at most.
  Every read sends it on, so the API refuses a revoked or expired token on its next read, and
  the server lets it in no more within that minute. A refused token is refused again for 10
  seconds without asking the API.
- A request body holds at most **1 MiB** and one JSON-RPC message (no batches).
- `read_module` gives up to 100,000 characters a call and a resource read up to 500,000. A longer
  text comes in parts by `cursor`, or says it was cut.

## Troubleshooting

**401 Unauthorized.** The header is missing, or the token is wrong, revoked or expired. The answer
names the reason: `unauthorized` (unknown or wrong), `token-revoked`, `token-expired`. A
deactivated service account is 403 `service-account-deactivated`. The header is exactly
`Authorization: Bearer <token>`, with no quotes or line break in the token. Check that the variable
your configuration names is set where the client runs (`echo ${#OPENFOLIA_MCP_TOKEN}` prints its
length: 90 for a service account token). A revoked or expired token does not come back: issue a new
one.

**403 `token-not-read-only`.** Your token's service account holds more than `content.read`
(drafts, editing, releases), so the server refuses it rather than show more. Use a token of an
account whose role holds `content.read` alone, made as in [Make a service account and token for
MCP](#make-a-service-account-and-token-for-mcp). Over stdio, every tool call fails with this code
instead.

**503 `The token could not be checked`.** The server did not reach the API to check your token, or too many checks were under way.
Nothing is counted against you: try again after the seconds `Retry-After` names.

**403 `Forbidden: origin not allowed`.** The request carried an `Origin` header, as a client running
in a browser does, and the server allows none by default (it protects against DNS rebinding). A
self-hoster adds the client's origin to `CCMS_MCP_HTTP_ALLOWED_ORIGINS`. Desktop and command-line
clients send no `Origin` and never see this.

**429.** `Too many failed attempts`: wrong tokens came from your address (or from many at once).
Fix the token, then wait the seconds `Retry-After` names. `Too many token checks at once`: your
address sent more than 4 new tokens at the same time. `Too many requests`: more than 600 a
minute from your address; slow the client down. A `busy` tool error means the server is already
running its 8 calls at once.

**404 at `/mcp`.** No MCP server runs on this instance (self-hosted: it is optional, see below), or
the URL has a path after `/mcp` or a trailing slash. While the MCP server restarts, `/mcp` answers 404
or **502** (it is there but did not answer) for up to 10 seconds after it is back.

## Moving from the shared token

Until v0.0.3, a self-hosted MCP server had one token for everyone, `CCMS_MCP_HTTP_TOKEN`, and every
caller read as the server's own service account, `CCMS_MCP_API_TOKEN`. That shared token is
**deprecated**: it still works in this release, and the server warns about it when it starts. It is
removed in v0.0.5.

1. Make a service account and token for each person or agent that connects, as in [Make a
   service account and token for MCP](#make-a-service-account-and-token-for-mcp). The account
   behind `CCMS_MCP_API_TOKEN` already holds `content.read` alone, so you can also issue more
   tokens of it, one per caller.
2. In each client, replace the shared token with the caller's own (in `OPENFOLIA_MCP_TOKEN`, say).
   Meanwhile, callers with their own tokens and callers still on the shared one are served side by
   side.
3. Once every client has moved, remove both settings and restart the server.

<ServerSetting>
  Remove [`CCMS_MCP_HTTP_TOKEN`](/reference/settings#ccms_mcp_http_token) and
  [`CCMS_MCP_API_TOKEN`](/reference/settings#ccms_mcp_api_token) from
  `deploy/.env`, then run `docker compose up -d`.
</ServerSetting>

## Running it yourself

In a container deployment the MCP server is the optional `mcp` service. Once it runs, the editor
serves it at its own address plus `/mcp`, and on the MCP port of the same machine. It needs no token
of its own: each caller brings one.

1. `COMPOSE_PROFILES=mcp` in `deploy/.env`, then `docker compose up -d --wait`.
2. For each caller, a service account and token, as in [Make a service account and token for
   MCP](#make-a-service-account-and-token-for-mcp).

The [install guide for coding agents](/agents), step 9, does each step with a check, and
[Self-hosting](/self-hosting) describes the deployment. Behind your own reverse proxy:

- **Timeouts:** allow at least 120 seconds for `/mcp`, the longest a call may take.
- **The caller's address:** the lockout and the rate limit count by it. The server believes the
  editor about it (`CCMS_MCP_HTTP_TRUST_PROXY=1`, the compose default). With a reverse proxy in
  front of the editor, set it to `2`, as you would `CCMS_TRUST_PROXY`, so that each caller counts
  on their own rather than all as your proxy. A count higher than the proxies really in front
  lets callers name any address. The server believes only the editor
  (`CCMS_MCP_HTTP_PROXY_ADDRESSES=editor`): a caller on the MCP port counts by its own address,
  whatever it sends.

The server's settings are in the [settings reference](/reference/settings), under "MCP server".
