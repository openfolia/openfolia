Das Portal ist eine statische Website der veröffentlichten Handbücher für eine Zielgruppe: eine
Website je Sprache, mit den Handbüchern je Produkt und Variante, Filtern, Suche im Browser, hell und
dunkel, im Branding Ihrer Organisation. Es wird mit dem Token eines Service-Accounts aus der API erstellt und braucht danach keine
API mehr: Jeder Server für statische Dateien liefert es aus.

## Ein Token vorbereiten

1. Wählen Sie die Zielgruppe, für die das Portal ist, eine Zielgruppe aus `openfolia.yaml` (in den
   Beispielinhalten `public`). Ein Build dient einer Zielgruppe.
2. Legen Sie einen Service-Account an, dessen Rollen nur `content.read` enthalten, jede mit einer
   Zielgruppengrenze von höchstens dieser Stufe (siehe
   [Service-Accounts und Tokens](/de/guide/admin/service-accounts)), und kopieren Sie sein Token.

Der Build weist ein Token zurück, das keinem Service-Account gehört, mehr als `content.read`
enthält oder über die Zielgruppe hinaus lesen darf. Er prüft jedes Handbuch und Modul beim Lesen
erneut, sodass nichts oberhalb der Zielgruppe in die Dateien gelangt.

## Erstellen

Aus einem Checkout des Repositorys:

```sh
CCMS_PORTAL_API_URL=https://docs.example.com/api \
CCMS_PORTAL_TOKEN="$PORTAL_TOKEN" \
CCMS_PORTAL_AUDIENCE=public \
pnpm nx run portal:site
```

| Einstellung             | Was                                                                                                        |
| ----------------------- | ---------------------------------------------------------------------------------------------------------- |
| `CCMS_PORTAL_API_URL`   | Die Adresse der API, `https://` (einfaches `http` nur zu diesem Rechner). Erforderlich.                    |
| `CCMS_PORTAL_TOKEN`     | Das Token des Service-Accounts. Nur im Header `Authorization` gesendet. Erforderlich.                      |
| `CCMS_PORTAL_AUDIENCE`  | Die Zielgruppe. Erforderlich.                                                                              |
| `CCMS_PORTAL_LANGUAGES` | Die Sprachen, durch Kommas getrennt (Standard: jede konfigurierte Sprache).                                |
| `CCMS_PORTAL_RELEASES`  | IDs von Veröffentlichungen, durch Kommas getrennt (Standard: die neueste nicht zurückgezogene je Produkt). |
| `CCMS_PORTAL_OUT_DIR`   | Wohin die Websites geschrieben werden (Standard: `frontend/portal/dist`).                                  |
| `CCMS_PORTAL_BASE_PATH` | Der Pfad, unter dem die Websites liegen, mit `/` am Anfang und Ende (Standard: `/`).                       |
| `CCMS_PORTAL_BRANDING`  | `on` (Standard) oder `off`: das Branding Ihrer Organisation oder das Standard-Aussehen von OpenFolia.      |

Die Ausgabe enthält einen Ordner je Sprache (`en/`, `de/`) und eine `index.html`, die Leser zur
ersten schickt. Sie ersetzt den Ausgabeordner erst, wenn jede Sprache erstellt ist. Vorher
durchsucht der Build jede Datei nach dem Token und bricht bei einem Treffer ab, und er bricht ab,
wenn die Bytes eines Bildes oder Anhangs nicht zu ihrem Hash passen. Erstellen Sie es nach jeder
Veröffentlichung neu.

## Was Leser sehen

- **Die Startseite** beginnt mit einem Suchfeld und listet die Handbücher jedes Produkts; **Alle
  Handbücher** listet jedes Handbuch mit Filtern für das Produkt, jedes Variantenmerkmal und den
  Titel.
- **Ein Handbuch** ist zum Lesen gesetzt: das Inhaltsverzeichnis daneben markiert den Abschnitt
  im Blick, ein Umschalter je Variantenmerkmal (Karosserie, Markt, …) öffnet dasselbe Handbuch in
  einer anderen Variante, und ein Link lädt das PDF der Veröffentlichung für diese Variante und
  Sprache, wenn es eines gibt.
- **Die Suche** findet Abschnitte wie Handbücher, gefiltert nach Produkt und Variante.
- **Das Branding** aus [Branding](/de/guide/admin/branding) (Name, Logos für hell und dunkel,
  Favicon, Farben) steht auf jeder Seite. Seine Farben gelten nur, wenn ihre Kontrastprüfungen
  bestehen; Sicherheitsfarben ändern sich nie. Erstellen Sie die Website nach einer Änderung neu.

## Bereitstellen

Liefern Sie den Ausgabeordner mit einem beliebigen Webserver für statische Dateien aus, unter einem
eigenen Hostnamen oder unter dem Basispfad. Das Portal hat keine Anmeldung: **Ein nicht
öffentliches Portal braucht eine Anmeldung davor**, die Ihres Proxys oder Ihres Hosters.

Jede Seite trägt ihre Content Security Policy als Meta-Tag, aber ein Meta-Tag kann nicht alles
ausdrücken. Der Host muss deshalb diese Header bei jeder Antwort senden:

- `Content-Security-Policy`, genau so:

  ```text
  default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
  ```

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Strict-Transport-Security: max-age=31536000`, über HTTPS

Senden Sie bei Anhängen, die als `.bin` geschrieben sind (`<lang>/assets/*.bin`), zusätzlich
`Content-Type: application/octet-stream` und `Content-Disposition: attachment`: Nicht jeder Server
kennt die Endung. Ein fehlender Pfad antwortet mit der `<lang>/404.html` seiner Sprache.

nginx (ein `add_header` in einer `location` ersetzt die des Servers, deshalb wiederholt die
`.bin`-`location` sie; `always` gibt auch Fehlerseiten die Header):

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name manuals.example.com;
    ssl_certificate     /etc/letsencrypt/live/manuals.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/manuals.example.com/privkey.pem;
    root /srv/portal;

    add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Strict-Transport-Security "max-age=31536000" always;

    location / {
        try_files $uri $uri/ =404;
    }
    location ~ /assets/[^/]+\.bin$ {
        types { }
        default_type application/octet-stream;
        add_header Content-Disposition "attachment" always;
        add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'" always;
        add_header X-Content-Type-Options "nosniff" always;
        add_header Referrer-Policy "strict-origin-when-cross-origin" always;
        add_header Strict-Transport-Security "max-age=31536000" always;
    }
    error_page 404 /en/404.html;
    location /en/ { error_page 404 /en/404.html; try_files $uri $uri/ =404; }
    location /de/ { error_page 404 /de/404.html; try_files $uri $uri/ =404; }
}
```

Caddy (die Header als Snippet, für die Dateien und die Fehlerseiten gleichermaßen):

```text
(portal-headers) {
	header {
		Content-Security-Policy "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'"
		X-Content-Type-Options "nosniff"
		Referrer-Policy "strict-origin-when-cross-origin"
		Strict-Transport-Security "max-age=31536000"
	}
}

manuals.example.com {
	root * /srv/portal
	import portal-headers
	@bin path_regexp /assets/[^/]+\.bin$
	header @bin {
		Content-Type "application/octet-stream"
		Content-Disposition "attachment"
	}
	file_server
	handle_errors {
		import portal-headers
		@en404 expression `{err.status_code} == 404 && {path}.startsWith("/en/")`
		@de404 expression `{err.status_code} == 404 && {path}.startsWith("/de/")`
		rewrite @en404 /en/404.html
		rewrite @de404 /de/404.html
		file_server
	}
}
```

Tragen Sie Ihre eigenen Sprachen anstelle von `en` und `de` ein. Bei einem Hoster, der eine
Header-Datei oder Einstellungen statt einer Serverkonfiguration nimmt, setzen Sie dieselben Header
dort: die vier für jeden Pfad und die zwei für `.bin`-Dateien.
