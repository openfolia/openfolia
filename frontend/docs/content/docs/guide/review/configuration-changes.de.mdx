Die Projekteinstellungen, die Begriffe und die Seitengestaltungen liegen in den Inhalten, neben den
Modulen. Eine Änderung daran kommt in eine Überarbeitung und durch dieselbe Prüfung: Nichts gilt,
bevor sie zusammengeführt ist.

## Die Änderung in einer Überarbeitung machen

1. Wählen oder beginnen Sie eine Überarbeitung. Wer die Projekteinstellungen ändert, sieht
   **Änderungen werden in der Überarbeitung „…“ gespeichert und vor dem Übernehmen geprüft.**
2. Ändern Sie die Einstellungen, einen Begriff oder eine Seitengestaltung.
3. Reichen Sie die Überarbeitung wie jede andere ein; siehe
   [Vom Entwurf nach main](/de/guide/review/workflow).

**In Prüfung öffnen** über den Einstellungen führt direkt zur Prüfung der Überarbeitung.

## Was die Prüfenden sehen

Jede solche Änderung ist ein eigenes Element, markiert als **Konfiguration**, **Begriff** oder
**Seitengestaltung**, mit der Datei, in der sie steht, etwa `openfolia.yaml`. **Was sich geändert hat:**
listet die geänderten Teile, etwa `moduleTypes/procedure`.

![Eine Überarbeitung, die die Projekteinstellungen ändert: das Element openfolia.yaml mit Was sich geändert hat, und die Freigaben](/images/guide/de/review-approvals.webp)

Diese Elemente sehen im Text, nebeneinander und gerendert gleich aus. Im Chip des Elements zählt
jeder geänderte Teil als **~1**.

## Was sie brauchen

- Eine Änderung der Projekteinstellungen braucht die Prüfung und jede Abzeichnung, die es gibt.
  Siehe [Freigaben und Abzeichnungen](/de/guide/review/approvals).
- Ein Begriff oder eine Seitengestaltung braucht nur die Prüfung.
- Prüfen darf sie nur, wessen Rolle alle Inhalte abdeckt.

Solange eine Überarbeitung die Projekteinstellungen ändert, kann keine andere es: **Eine andere
Überarbeitung ändert die Projekteinstellungen. Sobald diese zusammengeführt oder verworfen ist,
lassen sie sich hier ändern.**
