Personen können sich am Editor mit ihrer E-Mail-Adresse und einem Passwort anmelden. Das ist
standardmäßig eingeschaltet (`CCMS_PASSWORD_SIGN_IN`, `on` oder `off`), außer im Demo-Modus: Dort
ist es aus, und `on` wird beim Start abgelehnt. Es funktioniert neben [OpenID
Connect](/de/guide/self-hosting/oidc): Die Anmeldeseite zeigt dann das Formular und die Schaltfläche
des Anbieters.

`CCMS_PASSWORD_SIGN_IN` und `CCMS_INVITE_DAYS` gehören in `deploy/api.env`: `compose.yaml` gibt
sie aus `deploy/.env` nicht weiter.

## Der erste Admin

Setzen Sie entweder vor dem ersten Start `CCMS_FIRST_ADMIN_EMAIL`, wie der
[Schnellstart](/de/guide/self-hosting/quick-start) es tut, oder führen Sie jederzeit `first-admin`
aus:

```sh
docker compose exec api node dist/database/first-admin.main.js you@example.com \
  --name "Ihr Name" --editor https://docs.example.com/
```

Der Befehl legt den Benutzer an, bei Bedarf auch die Rolle `admin` mit allen Berechtigungen, und
gibt einen einmaligen Link aus, mit dem das Passwort gewählt wird. Der Link erscheint in Ihrem
Terminal, nie im Protokoll. Er funktioniert einmal, für `CCMS_INVITE_DAYS` Tage (Standard 7). Ein
erneuter Aufruf erzeugt einen neuen Link, und der frühere funktioniert nicht mehr. `--editor` ist
die Adresse des Editors, wie Personen ihn öffnen (Standard: `CCMS_PUBLIC_URL`).

## Alle anderen

Admins fügen Personen im Editor hinzu ([Benutzer und Rollen](/de/guide/admin/users-and-roles)). Eine
neue Person bekommt eine Einladung: einen einmaligen Link, der einmal zum Kopieren angezeigt und
zusätzlich per E-Mail verschickt wird, wenn [E-Mail](/de/guide/self-hosting/email) eingerichtet ist.
Ein Admin kann jederzeit eine neue Einladung oder einen Link zum Zurücksetzen erzeugen; der frühere
Link funktioniert dann nicht mehr. Eine Einladung gilt `CCMS_INVITE_DAYS` Tage, ein Link zum
Zurücksetzen eine Stunde.

**Passwort vergessen?** erscheint auf der Anmeldeseite nur, wenn E-Mail (`CCMS_MAIL_URL`) und
`CCMS_PUBLIC_URL` gesetzt sind. Die Antwort ist dieselbe, ob die Adresse bekannt ist oder nicht, und
ein Link zum Zurücksetzen geht nur an eine Person, die ein Passwort hat.

## Passwörter

- Zwischen 12 und 256 Zeichen, kein häufiges Passwort und nicht die eigene Adresse der Person.
  Regeln zu Zeichenklassen gibt es nicht.
- Gespeichert wird nur ein argon2id-Hash.
- Wer ein Passwort über einen Link setzt oder es im Kontomenü ändert, beendet seine anderen
  Sitzungen.

## Sperre

Fehlgeschlagene Anmeldungen zählen doppelt. Über einer der beiden Grenzen lautet die Antwort 429
`too-many-failed-attempts` mit `Retry-After`, bevor ein Passwort geprüft wird:

| Gezählt                   | Einstellung                                                      | Standard         |
| ------------------------- | ---------------------------------------------------------------- | ---------------- |
| je Client-Adresse         | `CCMS_AUTH_FAILURES_MAX`, `CCMS_AUTH_FAILURES_WINDOW_MS`         | 20 pro Minute    |
| je Konto (E-Mail-Adresse) | `CCMS_PASSWORD_FAILURES_MAX`, `CCMS_PASSWORD_FAILURES_WINDOW_MS` | 10 in 15 Minuten |

Die Zählung je Client-Adresse liegt im Speicher jedes Servers. Hinter einem Reverse Proxy teilen
sich alle Clients die Adresse des Proxys, solange `CCMS_TRUST_PROXY` nicht stimmt ([Reverse
Proxy](/de/guide/self-hosting/reverse-proxy)). Die Zählung je Konto liegt in der Datenbank,
gemeinsam für alle Server, und greift daher auch hinter einer gemeinsamen Adresse. Anfragen über
„Passwort vergessen“ zählen getrennt, sodass fehlgeschlagene Anmeldungen nie das Zurücksetzen
blockieren.

## Zwei-Faktor-Anmeldung

Personen können einen zweiten Schritt mit einer Authenticator-App hinzufügen, und ein Admin kann ihn
[vorschreiben](/de/guide/admin/two-factor). Sie braucht den
[Instanzschlüssel](/de/guide/self-hosting/secret-key), der das Geheimnis jeder Person versiegelt.
Falsche Codes zählen pro Person unter `CCMS_PASSWORD_FAILURES_MAX`, aber nie mehr als 10 pro
Zeitfenster, auch wenn die Einstellung höher oder 0 ist.

Wer das Telefon verloren hat, meldet sich mit einem Wiederherstellungscode an oder bittet einen Admin
um das Zurücksetzen. Gibt es keinen anderen Admin, setzen Sie auf der Kommandozeile des Servers
zurück:

```sh
docker compose exec api node dist/database/reset-second-factor.main.js you@example.com
```

Es entfernt den zweiten Faktor der Person und steht im Audit-Log. Bewahren Sie den geheimen Schlüssel
auf: Ohne ihn kann sich niemand mit einem Code anmelden, und wo die Zwei-Faktor-Anmeldung
vorgeschrieben ist, kann niemand sie einrichten.

## Sitzungen

Passwort-Sitzungen haben dieselben Grenzen wie die des Anbieters: 8 Stunden ohne Anfrage
(`CCMS_SESSION_IDLE_MINUTES`) und höchstens 7 Tage (`CCMS_SESSION_MAX_HOURS`). Ein Admin kann andere
Grenzen festlegen ([Single Sign-on vorschreiben](/de/guide/admin/single-sign-on)). Wo Single Sign-on
vorgeschrieben ist, meldet sich nur das Notfallkonto mit seinem Passwort an. Wird
`CCMS_PASSWORD_SIGN_IN` ausgeschaltet, enden die Passwort-Sitzungen.

## Das gemeinsame Token leer lassen

Wo sich Personen anmelden, lassen Sie `CCMS_API_TOKEN` und `CCMS_EDITOR_API_TOKEN` leer. Anders als
OpenID Connect lehnt die Passwort-Anmeldung das gemeinsame Token nicht ab, und damit liest jeder,
der den Editor erreicht, alle Entwürfe ohne Anmeldung. Die API warnt beim Start.

## Ohne Passwörter

`CCMS_PASSWORD_SIGN_IN=off` lässt OpenID Connect,
[Codes per E-Mail](/de/guide/self-hosting/email-code-sign-in) (nur mit `CCMS_EMAIL_CODE_SIGN_IN=on`)
und Tokens von Service-Accounts. Ist nichts davon eingerichtet, sagt die Anmeldeseite des Editors,
dass die Anmeldung nicht eingerichtet ist.
