Der Server versendet E-Mails über Ihren eigenen Mailserver (SMTP): Einladungen, Links zum
Zurücksetzen des Passworts, Anmeldecodes und andere Nachrichten. Ohne Mailserver wird nichts
versendet, und der Editor bietet Anmeldelinks stattdessen zum Kopieren an.

Jede E-Mail trägt Produktname, Logo und Farbe aus **Verwaltung › Branding**, ist in der Sprache
der Person geschrieben (Englisch oder Deutsch) und hat einen HTML- und einen Textteil. Ihre Links
beginnen alle mit `CCMS_PUBLIC_URL`.

## Einrichten

1. Tragen Sie die Einstellungen in `deploy/.env` ein (`compose.yaml` gibt sie an die API und an
   die Worker weiter, die die E-Mails versenden):

   ```sh
   CCMS_MAIL_URL=smtp://mail.example.com:587        # oder smtps://mail.example.com:465
   CCMS_MAIL_FROM=docs@example.com                  # nur die Adresse; der Absendername ist der Produktname
   CCMS_MAIL_USER=docs@example.com                  # nur wenn der Server eine Anmeldung verlangt
   CCMS_MAIL_PASSWORD_FILE=/run/secrets/mail-password
   CCMS_PUBLIC_URL=https://docs.example.com/        # die Basis jedes Links in einer E-Mail
   ```

   Die URL enthält nur Host und Port: nie einen Benutzer, ein Passwort, einen Pfad oder eine
   Abfrage.

2. Geben Sie den Containern die Passwortdatei als Compose-Secret, in einer
   `compose.override.yaml` neben `compose.yaml`:

   ```yaml
   services:
     api:
       secrets: [mail-password]
     worker:
       secrets: [mail-password]
   secrets:
     mail-password:
       file: /srv/secrets/mail-password
   ```

   Der Benutzer der Container muss die Datei lesen können; für andere auf dem Host bleibt sie
   unlesbar. `CCMS_MAIL_PASSWORD` geht auch, aber die Datei hat Vorrang, wenn beide gesetzt sind.
   Compose liest die Ergänzung nur, wenn weder `-f` noch `COMPOSE_FILE` angegeben ist: siehe [Eigene
   Ergänzungen](/de/guide/self-hosting/quick-start#schritt-für-schritt).

3. Starten Sie neu: `docker compose up -d --wait`.

## TLS

- `smtps://` verwendet TLS ab dem ersten Byte (Standard-Port 465).
- Bei `smtp://` (Standard-Port 587) ist STARTTLS Pflicht (`CCMS_MAIL_REQUIRE_TLS`, Standard
  `true`): Ein Server ohne STARTTLS bekommt nichts, nicht einmal die Anmeldung. Setzen Sie es nur
  für ein Relay in einem Netz, dem Sie vertrauen, auf `false`.
- Das Zertifikat des Servers wird immer geprüft. Hat eine private Zertifizierungsstelle es
  signiert, setzen Sie `CCMS_MAIL_CA_FILE` auf deren PEM-Datei.

## Der Instanzschlüssel

Eine wartende E-Mail wird mit dem [Instanzschlüssel](/de/guide/self-hosting/secret-key)
versiegelt, da sie einen Anmeldelink enthalten kann. Ohne Schlüssel bleibt E-Mail aus: Die API
protokolliert das beim Start, und **Verwaltung › System** nennt den Grund.

## Sprache

Eine E-Mail geht in der Sprache der Person hinaus, wenn der Server sie kennt, sonst in
`CCMS_MAIL_LANGUAGE` (`en` oder `de`, Standard `en`).

## Prüfen

1. Öffnen Sie **Verwaltung › System**. Die Karte **E-Mail** zeigt Server, TLS-Modus und Absender,
   nie den Benutzer oder das Passwort.
2. Wählen Sie **Test-E-Mail senden**. Sie geht an Ihre eigene Adresse.

E-Mails werden im Hintergrund versendet und wiederholt, sechsmal in wachsenden Abständen; eine
Ablehnung durch den Mailserver ist sofort endgültig. Eine E-Mail, die endgültig scheitert, steht
im [Audit-Log](/de/guide/admin/audit-log) als `mail.failed`, mit dem Grund, nie mit Adresse oder
Inhalt.

## Benachrichtigungs-E-Mails

Jede Person wählt je Art von Benachrichtigung, ob sie auch per E-Mail kommt, sofort oder in einer
täglichen Zusammenfassung ([Benachrichtigungen](/de/guide/getting-started/notifications)). Diese
E-Mails brauchen neben dem Mailserver und dem [Instanzschlüssel](/de/guide/self-hosting/secret-key)
`CCMS_PUBLIC_URL`: Die Schaltfläche in jeder E-Mail und der Link zum Abbestellen führen dorthin.
Fehlt eines der drei, sagt die Seite **Benachrichtigungen**, dass E-Mail ausgeschaltet ist und
warum; die Auswahl gilt weiter für die Glocke, und nichts wird zum Versand vorgemerkt.

Zwei Einstellungen, beide optional:

```sh
CCMS_NOTIFICATIONS_DIGEST_HOUR=8          # Stunde der täglichen Zusammenfassung, 0–23, für Personen ohne eigene Wahl
CCMS_NOTIFICATIONS_EMAILS_PER_HOUR=20     # höchstens so viele sofortige E-Mails pro Person und Stunde, 1–1000
```

- `CCMS_NOTIFICATIONS_DIGEST_HOUR` gilt in der Zeitzone jeder Person (UTC für Personen ohne
  Zeitzone). Standard `8`, also 08:00 Uhr.
- `CCMS_NOTIFICATIONS_EMAILS_PER_HOUR` ist ein Sicherheitsnetz: Darüber hinaus warten die E-Mails
  einer Person auf ihre tägliche Zusammenfassung. Standard `20`.

Jede Benachrichtigungs-E-Mail trägt die Kopfzeilen `List-Unsubscribe` und `List-Unsubscribe-Post`
(RFC 8058), damit ein Mailprogramm das Abbestellen mit einem Klick anbieten kann. Beide führen zu
`POST <öffentliche URL>/api/notifications/unsubscribe/<token>`. Das braucht keine Anmeldung und
stellt nur die Arten, um die es in der E-Mail ging, für diese Person und auf dem Weg, auf dem sie
kam (sofort oder in der Zusammenfassung), auf **Nur in der App**. Der Token ist mit dem geheimen
Schlüssel der Instanz versiegelt. Der Link im Text der E-Mail öffnet eine Seite des Editors, die
vor dem Absenden fragt. Ihr Reverse Proxy muss diesen Pfad
wie den Rest von `/api` an die API weitergeben.

Benachrichtigungs-E-Mails werden wie die anderen wiederholt. Jede gesendete steht im
[Audit-Log](/de/guide/admin/audit-log) als `mail.sent`, jede endgültig gescheiterte als
`mail.failed`, mit ihrer Art und der Person, für die sie war, nie mit ihrem Inhalt; ein
Abbestellen steht dort als `notification.unsubscribe`. **Verwaltung › System** zählt die
Fehlschläge der letzten 7 Tage und zeigt den jüngsten ([Die Seite System](/de/guide/admin/system#e-mail)).

## Was gespeichert bleibt

Eine wartende E-Mail liegt versiegelt in der Datenbank, bis sie versendet ist oder endgültig
gescheitert. Dann wird sie gelöscht; kein Text einer E-Mail bleibt gespeichert.
