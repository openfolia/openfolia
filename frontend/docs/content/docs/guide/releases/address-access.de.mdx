Wer die dauerhaften Adressen eines Projekts öffnen darf, steht in seiner Konfiguration. Der
Adressdialog sagt in einer Zeile über den Adressen, was gilt.

## Die drei Stufen

- **Diese Adressen kann jeder öffnen, ohne Anmeldung.** Die Adresse antwortet so, wie die
  Öffentlichkeit sie sieht, auch wenn jemand angemeldet ist: Was ein Leser über einen gedruckten
  Code bekommt, ist für alle gleich.
- **Diese Adressen öffnen nur Programme, die ein API-Token senden: Ein Browser oder ein gescannter
  Code kann sich dort noch nicht anmelden. Drucken Sie sie erst, wenn das Projekt sie öffentlich
  macht.**
- **Dauerhafte Adressen sind für dieses Projekt ausgeschaltet: Diese Adressen öffnen nichts.**

Die Stufe ist eine Einstellung des Projekts, geändert in einer geprüften Überarbeitung. Der Server
kann weniger erlauben, als das Projekt verlangt; dann öffnen sich die Adressen nur so weit, wie der
Server es erlaubt, und die Prüfungen jedes Handbuchs warnen mit **Zugriff auf Adressen begrenzt**.

## Links, die weiter funktionieren

- Tracking-Parameter wie `utm_source=newsletter` an einem geteilten Link werden ignoriert: Die
  Adresse öffnet wie ohne sie.
- Die Adresse eines Handbuchs lässt sich in den Auslieferungseinstellungen des Projekts ändern.
  Seine frühere Adresse öffnet es weiterhin. Ist eine Adresse oder frühere Adresse eines Handbuchs
  die ID eines anderen Handbuchs, melden die Prüfungen des Handbuchs **Adresse vergeben**: Ändern
  Sie eine der beiden.

Welche Tracking-Parameter ignoriert werden und wie viel der Server höchstens erlaubt, legt Ihre
Administration fest.
