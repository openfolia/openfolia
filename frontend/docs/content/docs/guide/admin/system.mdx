**Admin › System** shows the state of the installation. Most of it is set on the server: by whoever
runs it when OpenFolia is self-hosted, by your provider when it is hosted for you. The page says
what is set, and what to do when something needs attention.

![The System page with the storage used, the instance and the email section](/images/guide/en/admin-system.webp)

## Storage

**Storage** shows how much the installation uses: **Media (images and attachments)** and
**Archived PDFs (releases)**, which count towards a storage limit, and the Git content and the
database, for information.

When a limit is set, the page warns from 80 % of it. Once the limit is reached,
new uploads are refused. **Show unused files** opens the files nobody uses, to delete them.
**Largest files** lists the biggest uploads, each linking to the media library.

## Instance

**Instance** names the licence and where the source code is. **Secret key** says where the key
that protects stored secrets, such as webhook secrets, is kept. Back up that file. **Backups**
shows their status and links to [Backups](/guide/admin/backups).

## Email

**Email** shows whether the server sends email, and through which mail server. The settings are
in the server's environment, so they are read-only here.

- **Email is off: no mail server is set**: until one is set, sign-in links are shown to copy
  instead of being emailed.
- **Email is off: it needs the instance secret key**: a mail server is set, but the server has no
  secret key. **Where the secret key is set** jumps to it.

<ServerSetting>
  Email and the secret key are set up as in [Email](/guide/self-hosting/email)
  and [Instance secret key](/guide/self-hosting/secret-key).
</ServerSetting>

When email is on, **Send a test email** sends one to you. It should arrive within a minute; a
failure shows in the [audit log](/guide/admin/audit-log).

The section also counts the emails that failed for good in the last 7 days, and shows the newest
failure: when, which kind of email, and why. A failed email is first retried, at growing
intervals. The reasons:

- **rejected**: the mail server refused the email or the address.
- **unavailable**: the mail server could not be reached, or did not answer.
- **tls**: no secure connection could be made.
- **auth**: the mail server refused the sign-in.
- **unreadable**: the email could not be opened to send, for example after the secret key
  changed.
- **off**: email was turned off before the email went.

Every notification email sent is in the [audit log](/guide/admin/audit-log) as `mail.sent`, and
every email that failed for good as `mail.failed`, with its kind and the person it was for, never
what it said. People choose which notifications they get by email in
[Notifications](/guide/getting-started/notifications).

## Background work

**Background work** shows the workers that make release files, run imports and deliver webhooks:
how many run, how many jobs wait, and the longest wait.

- **Jobs are waiting, and no worker takes them**: the worker service is not running, or cannot
  reach the database.
- **Delivery is held after a restore**: the database was restored from another server, and
  notifications, webhooks and the change feed wait for one more step. **How to finish the
  restore** opens [After a restore](/guide/self-hosting/after-a-restore). Nothing is lost
  meanwhile.

<ServerSetting>
  Check the worker service as in [Workers](/guide/self-hosting/workers), and
  finish a restore as in [After a restore](/guide/self-hosting/after-a-restore).
</ServerSetting>
