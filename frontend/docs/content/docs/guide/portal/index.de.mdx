Im Portal finden Ihre Leser die veröffentlichten Anleitungen. Es ist eine statische Website, die aus
einer Veröffentlichung erstellt wird, im Branding Ihrer Organisation. Ist sie erstellt, braucht sie
weder den Editor noch die API: Jeder Webserver, der Dateien ausliefert, kann sie bereitstellen.

Autoren und Prüfer arbeiten nicht im Portal. Sie geben eine Veröffentlichung heraus, und das Portal
zeigt, was diese Veröffentlichung enthält.

## Wer es betreibt

- **Gehostet:** Ihr Anbieter kann das Portal für Sie betreiben, nach jeder Veröffentlichung neu
  erstellt; fragen Sie Ihren Anbieter oder Ihren Admin, ob er das tut und unter welcher Adresse. Ihr
  Team entscheidet weiter, was Leser sehen: das Branding ([Branding](/de/guide/portal/branding)) und
  die Zielgruppen in den [Projekteinstellungen](/de/guide/admin/project-settings).
- **Selbst betrieben:** Die Person, die Ihre Installation betreibt, erstellt es
  ([Erstellen und Vorschau](/de/guide/portal/build)) oder lässt es von der Container-Einrichtung
  betreiben, nach jeder Veröffentlichung neu erstellt ([Mit Docker Compose](/de/guide/portal/compose)).

## Was Leser sehen

- **Die Startseite** beginnt mit einem Suchfeld und listet die Anleitungen jedes Produkts.
  Sie kann eine eigene Überschrift, eine Einleitung, einen Hinweis und empfohlene Links tragen, in
  OpenFolia geschrieben: [Die Startseite einrichten](/de/guide/portal/start-page).
- **Alle Anleitungen** listet jede Anleitung, mit Filtern für das Produkt, jedes Variantenmerkmal
  und den Titel.
- **Eine Anleitung** ist zum Lesen gesetzt. Das Inhaltsverzeichnis neben dem Text markiert den
  Abschnitt im Blick. Ein Umschalter je Variantenmerkmal (Karosserie, Markt und so weiter) öffnet
  dieselbe Anleitung in einer anderen Variante. Ein Link lädt das PDF der Veröffentlichung für diese
  Variante und Sprache, wenn es eines gibt. Jeder Codeblock hat eine Kopieren-Schaltfläche (bei
  Maus und Tastatur beim Darüberfahren und Fokussieren sichtbar, auf Touch-Geräten immer), die den
  Code genau so kopiert, wie er geschrieben ist, und das bestätigt; gedruckt wird sie nicht.
- **Ein Update-Leitfaden** zeigt die Schritte für ein Update: Der Leser wählt die Version, die er
  hat, und die, auf die er geht, und hakt die Schritte ab. Siehe
  [Einen Update-Leitfaden lesen](/de/guide/portal/update-guides).
- **Ältere Versionen**, wenn das Portal mit ihnen erstellt wird: Die Versionszeile einer
  Anleitungsseite öffnet ein Menü der Versionen des Produkts, das Anleitung, Variante und Abschnitt
  behält; eine ältere Seite sagt, welche Version sie zeigt, und verlinkt die aktuelle. Siehe
  [Eine ältere Version lesen](/de/guide/portal/older-releases).
- **Die Suche** läuft im Browser und findet Abschnitte ebenso wie Anleitungen, gefiltert nach
  Produkt und Variante.
- **Sprachen und Aussehen**: eine Website je Sprache, standardmäßig Deutsch und Englisch, hell und
  dunkel, mit Ihrem Namen, Ihren Logos und Ihren Farben. Siehe [Branding](/de/guide/portal/branding).

## Ein Portal je Zielgruppe

Ein Portal dient einer Zielgruppe, einer Zielgruppenstufe aus den Projekteinstellungen wie `public`
oder `internal`. Nichts oberhalb dieser Stufe gelangt je in seine Dateien. Möchten Sie zwei
Zielgruppen bedienen, zum Beispiel Kunden und Ihr eigenes Servicepersonal, erstellen Sie zwei
Portale und stellen jedes dort bereit, wo sich seine Leser anmelden.

## Wann ein Portal sinnvoll ist

Ein Portal ist sinnvoll, wenn Leser die Anleitungen ohne Konto im Editor durchsuchen und lesen
sollen und das PDF allein nicht genügt. Soll eine eigene App oder ein eigener Suchindex den Inhalt
lesen, liefert ihn die [Delivery API](/de/guide/integrations/delivery-api) als Daten. Ein Portal
wird aus derselben API erstellt, beide stimmen also immer überein.
