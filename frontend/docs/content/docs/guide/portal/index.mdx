The portal is where your readers find the released manuals. It is a static site, built from a
release, in your organisation's branding. It needs no editor and no API once it is built: any web
server that serves files can host it.

Writers and reviewers do not work in the portal. They publish a release, and the portal shows what
that release holds.

## Who runs it

- **Hosted:** your provider can run the portal for you, rebuilt after each release; ask your
  provider or your admin whether yours does, and at which address. Your team still decides what
  readers see: the branding ([Branding](/guide/portal/branding)) and the audiences in the
  [project settings](/guide/admin/project-settings).
- **Self-hosted:** whoever runs your installation builds it ([Build and preview](/guide/portal/build)),
  or lets the container setup run it, rebuilt after each release
  ([With Docker Compose](/guide/portal/compose)).

## What readers see

- **The start page** leads with a search field and lists each product's manuals.
  It can carry your own heading, introduction, notice and featured links, written in OpenFolia:
  [Setting up the start page](/guide/portal/start-page).
- **All manuals** lists every manual, with filters for the product, each variant attribute and the
  title.
- **A manual** is set for reading. Its contents beside the text mark the section in view. A switch
  per variant attribute (body style, market, and so on) opens the same manual in another variant.
  A link downloads the release's PDF of that variant and language, when the release has one.
  Each code block has a copy button (shown on hover and focus, always on touch screens) that
  copies the code exactly as written and confirms it; the button is not printed.
- **An update guide** shows the steps for one update: the reader picks the version they are on
  and the one they are going to, and ticks the steps off. See
  [Reading an update guide](/guide/portal/update-guides).
- **Older releases**, when the portal is built with them: a manual page's release line opens a
  menu of the product's releases, which keeps the manual, variant and section; an older page says
  which release it is and links the latest. See
  [Reading an older release](/guide/portal/older-releases).
- **Search** runs in the browser and finds sections as well as manuals, filtered by product and
  variant.
- **Languages and looks**: one site per language, English and German by default, light and dark,
  with your name, logos and colours. See [Branding](/guide/portal/branding).

## One audience per portal

A portal serves one audience, an audience level from the project settings such as `public` or
`internal`. Nothing above that level is ever written into its files. To serve two audiences, for
example customers and your own service staff, build two portals and host each where its readers
sign in.

## When to use a portal

Use a portal when readers should browse and search the manuals without an account in the editor,
and the PDF alone is not enough. If an app or a search index of your own should read the content,
the [Delivery API](/guide/integrations/delivery-api) serves it as data. A portal is built from that
same API, so the two always agree.
