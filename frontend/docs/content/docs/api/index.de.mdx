## Konventionen

- **JSON:API:** Antworten sind `application/vnd.api+json`-Dokumente. Ressourcen sind
  `{ type, id, attributes, relationships, meta }`; `attributes` enthalten gespeicherte Daten,
  `meta`, was der Server daraus ableitet.
- **Listen sind seitenweise:** `page[number]` und `page[size]`, mit `meta.page` und `links`.
  Nicht dokumentierte Abfrageparameter werden mit 400 `unsupported-parameter` abgelehnt.
- **Fehler** sind `{ errors: [{ status, title, detail, code, source?, meta? }] }` auf jeder Route,
  mit einem stabilen `code`: siehe [Fehlercodes](/de/reference/errors).
- **Authentifizierung:** `Authorization: Bearer <token>`, das Token eines Dienstkontos. Jede
  Route braucht eine [Berechtigung](/de/reference/permissions).
- **Refs:** Inhaltsrouten lesen bei `?ref=` (ein Branch, ein Tag oder ein Commit), ohne Angabe beim
  Standard-Ref des Servers; jede Antwort nennt den gelesenen Commit in `X-Ccms-Commit`.
