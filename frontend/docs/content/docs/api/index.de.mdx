## Die Adresse Ihrer API und ein Token

Jede Anfrage geht an die Adresse Ihrer Instanz plus `/api`:

- **Gehostetes OpenFolia:** `https://<team>.openfolia.com/api`, mit dem Namen Ihres Teams.
- **Selbst betrieben:** die Adresse Ihres Editors plus `/api`, etwa `https://openfolia.example.com/api`.

Die Seite jeder Operation hat über der Operation ein Feld für Ihren Host; die Codebeispiele
verwenden ihn, und Ihr Browser behält ihn für die anderen Seiten. Diese Website sendet selbst
keine Anfragen: Kopieren Sie ein Beispiel und führen Sie es aus, oder öffnen Sie `/api/docs` auf
Ihrer Instanz (`https://<team>.openfolia.com/api/docs`), deren eigene interaktive Referenz, um
Anfragen dort auszuprobieren.

Eine Anfrage braucht ein Token: `Authorization: Bearer <token>`. Stellen Sie eines für einen
Service-Account unter **Verwaltung › Service-Accounts** aus
([Service-Accounts und Tokens](/de/guide/admin/service-accounts)); dafür brauchen Sie die
Berechtigung **admin.roles**. Wenn Sie sie nicht haben, bitten Sie eine Administratorin oder
einen Administrator um ein Token.

## Konventionen

- **JSON:API:** Antworten sind `application/vnd.api+json`-Dokumente. Ressourcen sind
  `{ type, id, attributes, relationships, meta }`; `attributes` enthalten gespeicherte Daten,
  `meta`, was der Server daraus ableitet.
- **Deaktivierte Personen:** Wo die Referenz `meta.people` aufführt, sagt eine Antwort, die Personen
  nennt (wer etwas geschrieben, freigegeben oder kommentiert hat), ob sie deaktiviert sind:
  `[{ "id", "deactivated" }]`, nur für Benutzer. Es ist der Stand beim Erstellen der Antwort, auch
  wenn Sie an einem Commit lesen.
- **Listen sind seitenweise:** `page[number]` und `page[size]`, mit `meta.page` und `links`.
  Nicht dokumentierte Abfrageparameter werden mit 400 `unsupported-parameter` abgelehnt.
- **Fehler** sind `{ errors: [{ status, title, detail, code, source?, meta? }] }` auf jeder Route,
  mit einem stabilen `code`: siehe [Fehlercodes](/de/reference/errors).
- **Authentifizierung:** `Authorization: Bearer <token>`, das Token eines Dienstkontos. Jede
  Route braucht eine [Berechtigung](/de/reference/permissions).
- **Refs:** Inhaltsrouten lesen bei `?ref=` (ein Branch, ein Tag oder ein Commit), ohne Angabe beim
  Standard-Ref des Servers; jede Antwort nennt den gelesenen Commit in `X-Ccms-Commit`.
